# Восстановление Web: текущая реализация

10.11.2026. Локальная main, без публикации. Этот документ уточняет прежние ограничения в BACKUP-CORE-SCOPE.md и WEB-RESTORE-07-5.md.

## Подключено

- Изолированная подготовка каталога, категорий, единиц, остатков, составов, модификаторов, раскладки, сотрудников и поставщиков; исходный файл сохраняется.
- Скидки, варианты доставки, шаблоны названий чеков — в рабочий каталог настроек.
- Компания, тема, принтеры, Telegram, backend — перенос параметров. После переключения набора device settings применяются до открытия рабочего UI; повтор после прерывания безопасен. Настройки backend привязываются к новому dataset. Сам импорт не отправляет сообщения, каталог или задания печати.
- Встроенные фотографии сохраняются локально. Внешние HTTPS-фотографии скачиваются при подготовке с ограничением размера и проверкой изображения. Недоступная фотография прерывает подготовку, не пропускается молча.
- Оплаченные Web-чеки и завершённые возвраты — отдельный неизменяемый исторический индекс, доступный в разделе «Чеки». Исходные строки и денежные значения сохранены, операции продажи/возврата повторно не исполняются.
- История чеков: SQL LIMIT51 отдельно по native/Web источникам, объединённая страница50; кнопка «Показать следующие 50». OFFSET продвигается только на использованные строки каждого источника.
- Смены: исходное состояние плюс отдельная историческая проекция итогов и движений для просмотра; кассовый baseline не проводится повторно.
- Native-копия импортированного набора включает индекс истории и актуальные изменённые настройки устройства.

## Границы

Исторические Web-чеки пока доступны для просмотра: новый возврат и повторная печать таких чеков не подключены. Native-аналитика исторических Web-продаж также требует отдельной интеграции. Не считать просмотр истории подтверждением этих сценариев.

История приёмок, черновики приёмки и инвентаризация остаются TODO по ранее согласованному объёму. Импорт открытых онлайн-контекстов/выбранных подарков сохраняет существующие ограничения и проверки; произвольная копия с такими состояниями может быть отклонена с объяснением.

## Проверки и приёмка

Добавлены JVM-тесты настроек/исторического индекса/смешанной пагинации и Android Room fixtures: rollback кандидата, фото, смены, archive roundtrip, SQL pagination. Android fixtures компилируются; на пользовательском планшете автоматически не исполняются. Результаты команд — harness/build-log.md. Ручная проверка: выбрать копию → preview → подтвердить замену → перезапуск → каталог/фото/настройки/смены/страницы чеков. Не выполнять пробную оплату или рассылку на production ради проверки.
