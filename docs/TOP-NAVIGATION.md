# Общая верхняя панель

Задача владельца от 2026-10-27: перенести меню pinned Web до следующих предметных этапов, затем подключать разделы по плану. Источник — `pos.html` на commit1682c88334e6fb13586ce4b530157c59ca062e43: `.topbar`/`.brand`/`.tabs`/`.tab`/`.events-tab`/`.shift-pill`/`.settings-topbar-btn`, `renderTopbar`; сокращение оператора — `Web/js/features/employees.js`, `employeeShortName`.

Все постоянные вкладки видимы. Для ещё не реализованных модулей открывается честная страница ожидания, без фиктивной статистики/сохранения. Счётчик событий и условное напоминание «Инвентаризация» появятся с источниками данных09/04; пустой счётчик/неактивная инвентаризация скрыты и в Web. Подключение этих функций не входит в этот UI-инкремент. Каталог остаётся текущей начальной страницей; отдельной вкладки «Товары» в исходной верхней панели нет, вход перенесён в настройки.

## NAV02: размеры и оформление

CSS px → dp/sp на одинаковой доступной ширине и font scale1. Manrope; navy #22273A (dark #10131A), white; неактивный текст white62%, активный фон white14%; shift фон white8%. Панель: padding12×16dp, gap10dp; tabs gap4dp, capsule radius100dp, padding8×14dp, label14sp/600; бренд14sp/700. События: SVG18dp, gap7dp; события и pill смены не получают tab.active, как в source renderTopbar; настройки44×44dp, SVG18dp/stroke1.8. Shift: gap8dp, padding8×14dp, label13.5sp/600; точка8dp с ореолом3dp. Активный оператор сокращается как в Web (фамилия + две инициалы), загрузка/ошибка не изображаются как закрытая смена.

Нормальная высота68dp, компактная62dp; системные safe insets отдельно. При ширине≤700dp: padding9×10dp/gap6dp, tab font12sp/padding8×11dp, shift11sp/padding7×10dp, бренд14sp. Settings44dp задаёт высоту строки. Native variant: текстовая capsule в44dp области нажатия; одна строка с горизонтальной прокруткой на узкой ширине/увеличенном системном шрифте вместо обрезки вкладок. Высота растёт с font scale. Это отдельный shared header variant, обычные кнопки48dp не меняются.

## NAV03: переходы и сохранение

Shared `MposTopBar` вызывается из `MposAppBar` через общий navigation context; у экранов нет копий вкладок/цветов/геометрии. Одна root route хранится `rememberSaveable`, активное состояние выводится из неё. Существующие callbacks/защита Back сохраняются. Экран-владелец задаёт enabled: каталог — закрытый editor и отсутствие записи; рабочая зона — отсутствие pending/modal; смена — отсутствие pending/dialog; оплата/возврат — прежний locked guard, включая неизвестный результат и уже оплаченные части; updater — отсутствие VERIFYING/INSTALLER. Смена pending блокирует глобальные переходы. Переход в каталог/debug через настройки использует тот же updater guard.

Меню не выдаёт финансовых команд, не меняет Room schema8, snapshots, identity/signing или данные. В isolated feature tests без root navigation context прежний appbar остаётся fallback; рабочее приложение использует общую панель. «Назад» оплаты остаётся отдельным действием под общей панелью.

## Приёмка

NAV01: переходы по всем постоянным вкладкам, реальные/будущие страницы и восстановление выбранной вкладки после Activity recreation. NAV02: широкая/узкая геометрия, прокрутка до настроек, активное состояние, screenshot на API36; парная Web/native сверка отдельно. NAV03: disabled callback и блокировка переходов из редактора; существующие sale/refund recovery tests должны остаться зелёными. Physical tablet acceptance отложен владельцем. Ссылки на выполненные проверки и ограничения — `harness/build-log.md`; наличие этого файла не означает verified.

Автоматизация APK-upgrade использует accessibility resource IDs `topNav-{route}`, экспортированные из shared header; подпись активного сотрудника не является селектором. Для старых опубликованных APK сохраняется fallback по прежним точным текстам. При наличии disabled modern ID fallback не применяется. NAV instrumentation проверяет реальное присутствие ID через AccessibilityNodeInfo.
