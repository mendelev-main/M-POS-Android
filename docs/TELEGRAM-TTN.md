# ТТН в рабочую группу — TG-TTN01–TG-TTN06

14.11.2026 владелец согласовал компактный табличный шаблон и подключение. Это новая функция поверх сохранённой native-приёмки, не требующая изменений backend.

- TG-TTN01: переключатель «ТТН в рабочую группу» в Telegram. По умолчанию выключен, старые настройки читаются без поля. Используются существующие botToken/chatId/threadId. При включении сохраняются дата начала и dataset: старые приёмки не рассылаются задним числом, после замены базы требуется пересохранить настройку для нового dataset.
- TG-TTN02: проведение приёмки разрешено только при открытой смене, независимо от admin-сессии и способа вызова репозитория. Проверка внутри транзакции до изменений склада/себестоимости. Имя кассира и timezone сохраняются в immutable PostedReceiving; новые optional JSON-поля не меняют прежние command fingerprints и чтение старых приёмок. Повтор успешно проведённой команды возвращает прежний результат даже после закрытия смены.
- TG-TTN03: картинка из сохранённого снимка: номер, дата ТТН и «Принята» в одной строке; одна полоса Поставщик/Принято/Сотрудник; товары, упаковки/вместимость, принятое количество в базовой единице, расчётная цена за единицу, суммы строк, итог. Без M POS, номера поставки и удалённого нижнего footer. Комментарий заказа, если есть, печатается после товаров. Деньги берутся из totalMinor; цена отображается HALF_UP до копеек, складские расчёты не меняются. «Принял» — фамилия/инициалы сохранённого кассира.
- TG-TTN04: подпись к фото/первой картинке альбома: «Поставщик: … / Дата: … / Принял: …». Дата — дата ТТН; время фактической приёмки отдельно на картинке. HTML-экранирование. Фото1200px, страницы не выше1600px; высота строк измеряется до разбивки, длинные названия не обрезаются. Итог только на последней странице; номер страницы появляется при нескольких страницах. До10 картинок — один sendMediaGroup; более10 — последовательные альбомы с отдельными durable batch keys, не обрезаем остаток документа.
- TG-TTN05: источник задания — подтверждённая запись PostedReceiving в БД, доступная только после commit. Callback ускоряет отправку, проверка каждые30сек работающего процесса/после перезапуска подбирает несданные задания после даты включения. При отсутствии validated network никакой sending marker не записывается: приёмка остаётся кандидатом после возврата связи. Историю не декодируем на каждом tick: сначала читается только revision, cache обновляется при изменении. Dataset/settings проверяются до подготовки/перед внешним эффектом. Ошибка Telegram не откатывает приход.
- TG-TTN06: существующий TelegramDelivery journal защищает от автоматической повторной отправки подтверждённых страниц/альбомов. Неопределённый timeout/обрыв после начала HTTP не повторяется вслепую; статус доступен в Telegram-настройках. Telegram не поддерживает idempotency key, поэтому exactly-once доставку при неизвестном результате гарантировать нельзя. 429 повторяется после retry_after. Проверки используют fake/localhost, реальные сообщения не отправляются.

## Ограничения

Это задачи работающего приложения, не WorkManager/foreground service: принудительно остановленный процесс отправит ожидающее после следующего запуска. Отключение/повторное включение переключателя задаёт новую дату начала; приёмки выключенного периода не досылаются. Смена dataset не переносит старую очередь в другую организацию. Онлайн-оплата/онлайн-заказы и владелец не участвуют в этом маршруте.

Старые приёмки без сохранённого сотрудника не достраиваются по нынешней смене: имя неизвестно. Новые создаются только из открытой смены. Фотографический образец Telegram и визуальное согласование реального PNG остаются ручной приёмкой владельца; HTML-макет сам по себе не доказывает совпадение Android renderer.

Отступы строк уменьшены, упаковка сохранена мелкой второй строкой. Количество страниц пересчитывается по новой высоте строк; финансовые данные и отправка прежние.
