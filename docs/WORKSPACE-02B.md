# Рабочая зона02b — отложенные заказы и резерв

Scope W03/W04/W05 и часть W06: сохранить/открыть/удалить parked, подпись/тип/комментарий/контакты доставки, общий current+parked reserve. Оплаты, печать кухни, customer/loyalty/WEB, тарифы доставки и explicit revalidation02c не входят. Android16+; physical tests отложены пользователем.

Pinned1682c883: parked-orders.js parkOrderNow/resumeParked/delete, uniqueParkedOrderLabel; android-pos-stock.js reservationSnapshot/checkedStockConsumption/openReference и android-safety critical journal. Source regressions park/resume/delete fault/double tap и shared ingredients. Native policy — CATALOG-WORKSPACE-SPEC/STATE-MACHINES: nonempty current никогда не заменяется молча.

Логический sessionId сохраняется при park/resume; новый current после park/clear/последней удалённой строки получает новый ID. Каждая UI cart-команда несёт expectedSessionId, чтобы задержанный tap прежнего заказа не попал в другой заказ. Add/step остаются delta/read-latest внутри этого владельца, SetQty/Details/Clear — CAS revision. Повтор commandId после lost response не переносит заказ второй раз. Legacy02a fingerprints сохраняются как lookup-only compatibility, новые записи включают sessionId.

Cart payload2 добавляет sessionId/createdAt/details. Payload1 current мигрирует одной Room transaction при initialize: строки, graph, revisions/result/stock сохраняются; новый ID и неизвестный старый createdAt получают время миграции (не историческое время создания). Layout остаётся payload1. Новые parked:<sessionId> документы содержат cart2+parkedAt. orders document — монотонный registry revision. Room schema5 не меняется: нет новых SQL columns. Unknown payload не reset. Парковочная row revision = следующий registry revision, чтобы старый parked revision не совпал после resume/repark того же session (ABA).

Park непустого current: label обязателен; сохранить parked snapshot, новый пустой current, registry/result/audit в одной transaction. Resume в пустой current: заменить current + удалить parked atomically; резерв переносится без повторного сложения. При непустом current UI предлагает отмену либо «Отложить и открыть» с подписью — atomic swap. Если у пустого current уже введены параметры, замена требует отдельного подтверждения. Delete parked и Clear current — подтверждение. Любой отказ записи/конфликт оставляет обоих владельцев/резерв и старые metadata. Физический ledger не меняется.

Подпись optional для current, обязательна при park; до80 Unicode code points. Как Web: trim/NFC/case/whitespace duplicate key и auto suffix «(2)», «(3)»; native обрезает основу для суффикса в пределах80. Тип here/takeaway/delivery. Comment до1000 code points, address500, phone40; переключение с delivery очищает скрытые контакты. Тариф/доставка не прибавляются к preview: здесь ещё нет этих денежных полей. До100 parked с явной ошибкой лимита; не скрытый Web limit. Поля клиента/WEB подключаются в своих этапах и не выдумываются сейчас.

Резерв выводится из snapshots; per-session RecipeCalculator агрегирует все строки до scale12, затем reserves разных sessions суммируются точно. Add/increase проверяет весь кандидат + все остальные parked, исключая прежний current reserve. noStockTracking/allowNegativeStock учитываются per simple. Park/resume не требуют заново переписывать stale/дефицитный заказ: его можно открыть для исправления, но increase/add всё ещё заблокированы stale guard; явный пересчёт02c впереди. Catalog delete guard учитывает зависимости всех parked. Preview плиток использует тот же parked reserve.

Gates: pure metadata/unique labels/flags/aggregate reserves; actual Room park/resume/swap/delete rollback/replay/concurrency/ABA/ownership/reopen/legacy payload; Compose cancellation/parked list/swap/metadata restore; updater preserves current+parked after actual APK replacement. Results в harness/build-log, статус до CI implemented, не full02/device-verified.
