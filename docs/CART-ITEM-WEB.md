# Позиция текущего заказа: окно Web

Локально от 2026-11-07. Источник: pinned `cart-presentation.js`, openCartItemModal/changeCartItemModalQty/selectCartDiscount/saveCartItemOptions; pos.html; C01-light.png и measurements/C01-light.json. Рабочий цикл mpos-phase/mpos-domain; визуальная приёмка владельцем в Android Studio pending, публикация отдельно.

## Поведение

Нажатие позиции открывает окно с её названием. Далее: количество (минус / число / плюс), комментарий к товару, сетка скидок с «Без скидки», пояснение о применении только к этой строке, «Отмена» / «Сохранить». Лишние кнопки старого native-окна убраны. Закрытие Back/вне окна эквивалентно отмене.

Количество, комментарий и выбранная скидка — локальный черновик. Нажатие +/- или карточки скидки ничего не записывает. Save отправляет одну SetOptions с owner/revision и новым command ID; окно закрывается только после успешной транзакции. Ошибка остатков/записи остаётся в окне; строка не меняется частично. Повтор command ID не повторяет редактирование; другие данные под тем же ID отклоняются. Изменения после начала частичной оплаты по-прежнему запрещены прежним guard.

Обычный счётчик не опускается ниже 1, как в Web. Для уже существующей дробной позиции native сохраняет её точное количество и исходную нижнюю границу (0,25 → плюс → 1,25 → минус → 0,25), не округляет её молча до единицы. Это осознанное отличие: в Web Math.max(1, qty) может изменить такую позицию даже при простом сохранении. Лимит комментария native — 1000 символов, поддерживает переносы строк.

Скидки берутся из действующего справочника. Выбранные имя/тип/значение сохраняются снимком в строке; «Без скидки» явно перекрывает также старые импортированные defaults. Если сохранённый снимок отсутствует в справочнике, отдельная карточка позволяет сохранить его или снять. Изменение/удаление определения не переписывает ранее сохранённые снимки (контракт SETTINGS-CATALOGS). Деньги рассчитывает существующий SaleMoney: фиксированная скидка на единицу, HALF_UP по строке. Итог строки и заказа, список отложенных и экран пересчёта показывают сохранённую скидку; оплата получает её через прежние defaults формы.

Комментарий виден в строке текущего заказа и историческом чеке. Все новые поля проходят через текущий/отложенный заказ и сохранённый чек; пересчёт рецептуры сохраняет комментарий и скидку. Добавление той же позиции продолжает увеличивать количество существующей строки с её настройками.

Удаление не находится в Web-модальном окне: строку можно смахнуть влево. Native сохраняет её до успешного удаления из БД; при ошибке она остаётся. Добавлено доступное действие «Удалить позицию» для assistive UI.

## Визуальный контракт C01

Измеренный Web: modal wide 560 dp, padding28, radius22; title18/24/800 и margin16; счётчик46×46/radius14, gap12, число22/30/min-width52. Комментарий — textarea80 dp, monospace15 (из computed Web metrics), border1,5/radius10/padding12×14. Скидки — две колонки/gap8/min48/radius12, выделение из общей primaryContainer. Пояснение — общие warning-цвета Web, radius14; действия gap10/radius16/font14,5. Высота ограничена, есть прокрутка и прежняя политика скрытия status bar. Точная парная проверка обеих тем остаётся отдельно.

## Хранение и проверки

CartLine получил optional comment/discountId/discount/discountEdited. WorkspaceCodec payload3 читает старые документы без этих полей; пустые defaults не добавляются в JSON. SQL-схема не менялась. Нативное восстановление использует тот же codec. SetOptions добавляет собственный fingerprint, не меняя прежние команды. Увеличение количества проверяет свежесть каталога и остаток с резервами; уменьшение по-прежнему может исправить дефицит.

Адресные JVM: CartItemOptionsTest (общая запись/валидация/остатки/пересчёт), CartItemStepTest (минимум и дроби), WorkspaceRulesTest (старые ограничения корзины), OrderSettingsTotalTest (нетто, доставка и явное снятие импортированной скидки). API: CartItemStorageTest (повтор/откат/park-resume/codec), CartItemWindowTest (черновик/отмена/save/смахивание), адаптированы WorkspaceUiTest и WorkspaceScaleUiTest. Запуск на устройстве и визуальная приёмка pending; результаты компиляции и JVM — harness/build-log.md.
