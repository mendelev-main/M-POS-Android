# Параметры текущего заказа: перенос Web

Локально от 2026-11-07, состояния C04/C05. Источник: pinned `Web/js/features/cart-presentation.js`, openOrderSettings/setOrderType/selectDeliveryTariff/saveOrderSettings, CSS pos.html и C05-light.png из Web-атласа. mpos-phase/mpos-domain; изменения без публикации, визуальная приёмка владельцем pending.

## Реализованное поведение

Нажатие поля «На месте» в текущем заказе открывает «Параметры заказа». Порядок как в Web:

1. Три кнопки «На месте», «С собой», «Доставка» с выделением выбранной.
2. Название / подпись чека, имя клиента, телефон — необязательные поля.
3. Только для доставки: адрес, кнопки настроенных тарифов, итог с доставкой. Если тарифов нет — пояснение о настройках; если сохранённый тариф отсутствует в справочнике — показан его снимок.
4. «Отмена» и «Сохранить»; закрытие по Back/вне окна без дополнительной кнопки-крестика, как в исходном showModal.

Тип и тариф сохраняются **немедленно** через прежний SetDetails, без закрытия окна. После успешной записи форма перечитывается: несохранённые текстовые изменения сбрасываются как при Web render/openOrderSettings. Нажатие уже выбранного типа в native не выполняет лишнюю запись и сохраняет текущий ввод. «Отмена» отбрасывает только текстовый ввод, не откатывает ранее записанные выборы. Ошибка записи оставляет окно открытым и показывает сообщение.

Кнопка «Сохранить» записывает подпись, имя, телефон и адрес; для недоставочного заказа адрес очищается именно здесь. Телефон/имя доступны для любого типа. Переключение типа сбрасывает выбранный тариф, но не удаляет сохранённые контакты. Комментарий заказа не редактируется в этом окне (в Web его здесь нет), существующий комментарий сохраняется.

Тариф — снимок ID/названия/суммы/версии. Он переносится в отложенный заказ и возвращается при открытии; поступает в начальную форму оплаты, не прибавляется повторно. Итог текущего заказа/модального окна использует существующий SaleMoney с принятым округлением строк и добавляет доставку один раз. Без выбранного тарифа показывается сумма товаров; обязательность выбора перед оплатой и расход наличных курьеру остаются в прежних use cases. Контакты заказа не реализуют отложенный модуль клиентов/лояльности06.

## Оформление

Модальная карточка до 460 dp, радиус22, padding28, прокрутка до92% высоты; заголовок18/800 и нижний отступ16. Поля имеют внешние подписи12,5/700 с gap6, input15/padding12×14/border1,5/radius10. Три варианта типа и тарифы — flex-row/gap10, border1,5/radius10, selected из общей primaryContainer. Итог24/800. Действия gap10/radius16/font14,5/min48; shared PosControl.Secondary — документированный вариант фон/чернила без рамки для Web btn-secondary. Используется общая явная тема; политика скрытия status bar сохранена и в новом Dialog.

## Сохранность и совместимость

SQL-схема не менялась. OrderDetails получил customerName, deliveryTariff и deliveryEdited. WorkspaceCodec читает старые payload1–3; новые поля добавлены как необязательные расширения details в payload3 и не выводятся при значениях по умолчанию. Старые заказы, отложенные и исторические чеки продолжают читаться. Native-копия переносит поля внутри существующего current/parked/receipt документа. Исторические импортированные снимки не переписываются. deliveryEdited отделяет явный сброс от прежних импортированных defaults, чтобы отменённый тариф не появлялся снова.

Fingerprint SetDetails включает новые поля при наличии, сохраняя прежний формат для старых команд. Owner/revision/idempotency/транзакция и запрет изменений после частичной оплаты сохранены. Успех/закрытие — после commit. Повтор команды с другим именем или тарифом отклоняется.
