## 07.4d.1 — OP01–OP06

- OP01: current и parked дают отдельные read-only WebOpenOperation с source-file-scoped origin, source IDs/location/times, исходными line names/price/qty/basePrice/manualPrice/comments/modifiers и найденной в этой же копии discount definition. Повтор для идентичного файла детерминирован, source objects не меняются. Origin не является payment command ID; другой export даёт другой origin. Нет смешивания с target30 или локальными командами.
- OP02: проверочный total = сумма line net HALF_UP2 + delivery. Проценты рассчитываются точно, без промежуточного округления; fixed discount — за единицу с ограничением gross; percent ограничивается100 как Web. Две строки0.05×3−10% →0.14+0.14=0.28; source draft0.27 остаётся0.27, accepted0.10/unpaid0.17 не переписываются, появляется quoteTotalMismatch. Missing price/qty/discount →unknown total и blocker, не0 и не fallback из products.
- OP03: доставка добавляется только для исходного типа «Доставка», fee берётся из session; отсутствие подтверждения тарифа явно отмечается. Неизвестный тип не становится «На месте». Modifier delta уже включён в item.price, не начисляется ещё раз. Лояльность06 остаётся TODO, но положительный reward делает quote unavailable; accepted payments сохраняются. Нельзя убрать reward и повысить unpaid amount.
- OP04: единственная открытая source shift и её source actor — только кандидаты для дальнейшей сверки, не доказанный historical binding. Для paid session проверяются createdAt/payment updatedAt против openedAt; missing/предшествующая смене дата явно блокирует подтверждение. Source parked employeeName/timestamp сохраняются отдельно от candidate actor; автора отложенного не заменять сегодняшним кассиром. Для обычного unpaid parked не требовать, чтобы он был создан уже после открытия сегодняшней смены.
- OP05: payment facts07.4a сохраняют paid cash40/given50/change10/unpaid card60. All-paid draft требует сверки завершённого чека, не нового списания. Чек той же суммы в кандидатной смене — возможное пересечение, а не доказательство дубля; ни paid evidence, ни completed receipt не удаляются. Положительный webOrderId требует решения о completion отложенного09, его нельзя забыть из-за отсутствия сетевого UI.
- OP06: duplicate parked/line/modifier/discount IDs, malformed/negative/overflowing money, nonpositive quantities, invalid types/time/currency отказываются. Пустой unpaid current не создаёт операцию; пустой paid current сохраняет money evidence с blocker. Для qty точнее scale12 ставится reconciliation flag, без округления source quantities. Прямых Room/stock/cash/transport/print writes нет.

Все результаты сохраняют operationalCartMappingPending и cashHistoryReconciliationPending. Для paid есть sourceQuoteNotPersisted: совпадение расчёта с totalCents не доказывает, что каталожная рецептура/discount definition не менялась после приёма части. Нет readyToActivate/Charge API. DTO не заменяет полный исходный файл, который07.4e должен сохранить отдельно; тарифные/print/loyalty/online metadata нельзя молча потерять при последующей materialization.
