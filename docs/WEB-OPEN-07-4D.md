## 07.4d.1 — OP01–OP06

- OP01: current и parked дают отдельные read-only WebOpenOperation с source-file-scoped origin, source IDs/location/times, исходными line names/price/qty/basePrice/manualPrice/comments/modifiers и найденной в этой же копии discount definition. - OP02: проверочный total = сумма line net HALF_UP2 + delivery. Проценты рассчитываются точно, без промежуточного округления; fixed discount — за единицу с ограничением gross; percent ограничивается100 как Web. - OP03: доставка добавляется только для исходного типа «Доставка», fee берётся из session; отсутствие подтверждения тарифа явно отмечается. Неизвестный тип не становится «На месте». Modifier delta уже включён в item.price, не начисляется ещё раз. Лояльность06 остаётся TODO, но положительный reward делает quote unavailable; accepted payments сохраняются. Нельзя убрать reward и повысить unpaid amount.
- OP04: единственная открытая source shift и её source actor — только кандидаты для дальнейшей сверки, не доказанный historical binding. Source parked employeeName/timestamp сохраняются отдельно от candidate actor; автора отложенного не заменять сегодняшним кассиром. ## 07.4d.2a — CR01–CR06: сверка кассовых фактов

- CR04: для full refund cash allocation сверяется с source withdrawal по return shift/точному returnedAt/сумме и количеству. ## 07.4d.2b — RG07–RG12: единица продажи и native recipe binding

Статус: implemented, локальные284JVM/lint/debug/preflight и16Python tests passed; CI/device не заявляются. `WebRecipeBinding` связывает frozen OP-строки с native RecipeRequest/RecipeProduct и проверяет расход. Это не запись CurrentCart2 и не разрешение продолжить оплату.

- RG07: source quantity/price/name/category/discount/modifier snapshots не переписываются по каталогу. Для simple basis=stock-unit, физическое количество на одну продажную единицу1 в source stockUnit; stockDisplayUnit не меняет количество/цену. Для composite basis=recipe-batch: запрос на одну проданную единицу равен recipeYield в recipeUnit. Две партии по10BYN с выходом3кг сохраняют source qty2/price10 и дают physical requests6кг, без деления10/3 и выдуманной цены за кг. Basis хранится явно рядом с исходной строкой: нельзя подписать число партий как килограммы.
- RG08: используется converted catalog07.4b и достижимый native RecipeProduct graph. Вложенные batch quantities и selected composite modifiers умножаются на выход соответствующего child ровно один раз. Для расхода применяется native RecipeCalculator. Независимый oracle читает raw source components и повторяет pinned productIngredients через точное BigDecimal multiplication; он не выводится из уже converted physical quantities. Расходы сравниваются численно без ложного несовпадения scale.
- RG09: modifiers сохраняют исходные product/qty/priceDelta/names. Saved qty определяет physical request; нынешняя option definition не подставляет новую qty/цену и не увеличивает уже включённую в item.price доплату. Удалённая/изменённая definition и неполная selection дают gaps, даже если известный source product позволяет посчитать расход. Missing sold/modifier product или qty не превращают нужный резерв в пустой map.
- RG10: noStockTracking/allowNegativeStock применяются по simple leaf, не по родительскому composite. Untracked leaf исключается из stock consumption, но участвует в cost. Cost каждого sold line проверяется независимо по raw-source expansion с учётом всех leaf costs и HALF_UP до копейки, затем строки складываются. Нулевые/неизвестные cost не взаимозаменяемы: при missing cost нет fake Simple(cost=0), graph/cost/native consumption остаются unknown. Missing stock balance не становится0.
- RG11: native расход должен точно совпасть с raw-source multiplication. Underflow и иное округление scale12 дают explicit gap и unknown aggregate reservation, а не незаметное изменение склада. Source sale qty точнее native scale9 и price точнее2 сохраняются с отдельным unsupported flag. Source line unit, отличающийся от stock basis, не приводит к угаданной конвертации. Known current+parked consumptions складываются; shortage проверяется по общему резерву с leaf negative-sale permissions. Если хотя бы один cart неполон, aggregate unknown, valid siblings не выдаются за весь резерв.
- RG12: циклы, missing ingredients и несовместимые единицы отказываются в catalog mapper. Shared DAG может иметь экспоненциальное expansion при малом файле; memoized work-count проверяется до calculator/oracle, суммарный лимит100000 source visits. Превышение recipeBindingLimit отказывается, не возвращая ложный пустой резерв. Во всех остальных результатах остаётся nativeCartEncodingPending; sourceRecipeAtExportOnly для paid означает, что source graph существует на export, а не доказан как исторический graph при приёме40.

Чистый adapter не создаёт revision1/command result, не зовёт CartEngine.Add, не записывает CurrentCart2 и не исполняет Sale/Refund. CurrentCart2 не хранит эту source selling basis; притвориться его обычной строкой до versioned encoding нельзя.07.4d.3 должен сохранить basis/paid provenance и реализовать совместимый native путь продолжения с транзакциями/replay/fault/reopen.07.4e материализует полный dataset; native restore validator нельзя ослабить ради принятия adapter DTO. Для incomplete графа граф/резерв null, а не частично валидный объект с выдуманными нулями.

Pinned source: pos.html/productIngredients/stockConsumptionFor/checkedStockConsumption, android-pos-stock.js (точность и совместный reserve current+parked), cart-composition.js/readModifierSelection+addConfiguredCartItem. Source unit graph не берётся из каталога целевого native-приложения.
