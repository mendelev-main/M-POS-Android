# Рабочая зона и настройки: локальные правки

Запрос владельца от 2026-11-07. Используется mpos-phase: pinned source → локальный код и регрессионные сценарии → запись результатов → визуальная приёмка владельцем в Android Studio. Публикация отдельно по прямой команде.

## Рабочая зона

Лупа и открываемое ею поле удалены из toolbar. Поиск каталога товаров не изменялся.

Найдены два источника визуальных скачков при добавлении: WorkspaceHome отключал все плитки при pending > 0, а MposWorkspaceTile менял прозрачность всего содержимого до 0,42; условная строка «Сохраняем…» меняла высоту footer заказа. Обычные плитки теперь используют тот же предел очереди, что и сетка категории: pending < 100. В режиме редактирования раскладки прежняя блокировка при pending сохранена. Динамическая строка удалена; toolbar и действия заказа сохраняют оформление при краткой блокировке записи через документированный вариант retainingAppearance. Disabled semantics и обработка нажатий остаются заблокированными. Оплата/отложение доступны только после завершения записи; ошибки сохранения по-прежнему показываются. Запись и расчёты не менялись. Окончательное исчезновение мерцания требует проверки владельцем.

Регрессия WorkspaceAppearanceTest проверяет отсутствие лупы, неизменные границы итога и оплаты при переходе pending 0 → 1, блокировку платежа. Сценарии отложенных заказов и нагрузочный сценарий переведены с удалённого поиска на навигацию категории; нагрузочный сценарий по-прежнему загружает 2000 товаров, оценивает видимые плитки и добавляет товар.

## Настройки

Просмотрены pinned `pos.html` renderSettingsScreen, CSS settings-* и android-admin.js; снимок K01-light.png из Web-атласа. Заголовок, основные действия и сетка идут в исходном порядке: панель администратора (только в административной сессии), товары, резервная копия; затем сотрудники/поставщики, доставка/скидки, шаблоны чеков. Основные кнопки — pill, min-height 52 dp; карточки — радиус 22 dp, padding 20 dp, gap 16 dp, колонки 1,2:0,8, до 700 dp одна колонка. Поля страницы: 22/26/40 dp. Это документированные варианты общих цветов/шрифта для Web settings.

Сотрудники и поставщики загружаются из текущих native-справочников при входе в настройки; ошибки чтения показываются явно. Кнопки открывают действующие страницы управления. Восклицательный знак рядом с заголовком открывает прежнее окно обновлений, индикатор наличия обновления сохранён. Склад и инвентаризация доступны через административную панель.

Оставшиеся различия: редактирование сотрудников/поставщиков открывается существующими страницами; inline-редакторы, удаление и рейтинговые короны Web ещё не перенесены. Ручная тема и справочники затем подключены по следующему запросу владельца: актуальный контракт — [SETTINGS-CATALOGS](SETTINGS-CATALOGS.md). Административная панель сохраняет текущий native-диалог. Полное попиксельное соответствие K01/K03 не заявлено.

## Проверки

Локально успешно: compileDebugKotlin и compileDebugAndroidTestKotlin, лог `work/workspace-settings-check.log`; Gradle 8.13 / JDK17 / API36. Компиляция выполнялась in-process после запрета среды на создание Kotlin daemon marker в Library. Регрессионные UI-тесты добавлены/адаптированы и скомпилированы, на устройстве не запускались. Визуальная приёмка — pending. Коммиты, push и релиз не выполнялись.
