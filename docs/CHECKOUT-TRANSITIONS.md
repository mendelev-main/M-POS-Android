# Переходы оплаты и текущий заказ

10.11.2026. Локальная main, без push. Уточнение владельца отменяет прежний UI-запрет «Назад» после подтверждения части; неизменяемость отдельной оплаченной части остаётся.

CT01 implemented: вход в SaleScreen закрыт entryReady gate до свежего чтения. При повторном входе не рисуются старые preview/completed/split. После acknowledgement результата ViewModel читает новое состояние перед уходом в workspace. Восстановление durable незавершённой оплаты по-прежнему работает; persisted unacknowledged receipt не скрывается.
CT02 implemented: Split controls retainingAppearance=true: pending запрещает повторный tap, но не меняет alpha цены/подписи. Частичные изменения читают только актуальную финансовую часть, без загрузки истории чеков50 и refunds на каждый tap.
CT03 implemented: «Назад» и системный Back в незавершённой native-раздельной оплате отменяют её внутренний учёт и возвращают стандартный экран оплаты. Товары/состав текущего заказа, склад, касса и receipts не меняются. Atomic cancel записывает tombstones split/checkout, result и audit; replay/старый commit защищены. Это ручной учёт, а не банковская отмена: реальный платёж терминала возвращается/отменяется на терминале отдельно.
Важная граница: importedOrigin (частично оплаченный Web-заказ) пока запрещён для новой cancel-команды, чтобы не потерять перенесённые доказательства оплаты; показывается объяснение. Отдельная реализация возврата импортированной предоплаты требуется прежде снятия ограничения.
CT04 implemented: подпись строки — цена · ×количество (без «порция рецепта» и лишнего unit в этой строке); swipe — урна на красном фоне с прежним доступным действием удаления.
CT05 implemented: rememberLazyListState + animateScrollToItem по подтверждённому приросту количества/новой строке; одинаковые строки подсвечиваются и прокручиваются к себе. Список не прыгает при удалении или уменьшении количества.

Проверки: JVM sale/payment input; main/Android fixtures compilation. Новые Room fault/replay cancellation, VM finish/open/new cart и UI long cart/autoscroll/swipe tests только скомпилированы; runtime/device acceptance владельцем pending. Плавность кадров не подтверждается компиляцией. Реальные оплаты, печать/Telegram/user DB не запускались.
