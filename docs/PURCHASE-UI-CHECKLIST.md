# Заказы поставщикам: сверка с Web

Источник: pinned `purchase-orders.js` и текущий одноимённый файл M-POS-Android-Web, просмотренный 08.11.2026. Статус ниже — implemented, не device-verified. Визуальное подтверждение выполняется владельцем в Android Studio.

| Пункт | Реализация | Проверка на планшете |
|---|---|---|
| История / Новый заказ | Полноширинные кнопки 54dp, радиус 14dp; независимое раскрытие | Открыть оба блока |
| История | Поставщик, дата, количество строк, статус, карандаш ожидаемого заказа | Проверить длинные названия и статусы |
| Строки заказа | Название, остаток, количество, единица заказа, содержимое упаковки, ожидаемое поступление | Проверить шт., кг, л и упаковки |
| Ввод количества | Цифровая клавиатура, запятая, удаление, очистка, подтверждение | Проверить замену первого ввода и очистку |
| Адаптация ширины | Поля рядом на широком экране, перенос на узком | Поворот планшета |
| Формирование | Сохранение актуального ввода и создание заказа одной кнопкой; блокировка повторного нажатия | Изменить количество и сформировать |
| Карточка заказа | Текст заказа, копирование, системное «Поделиться», «Готово» | Проверить буфер и системное меню |
| Редактирование | Общие строки и клавиатура с новой формой | Изменить упаковку ожидаемого заказа |
| Native операции | Приёмка, отмена, права, восстановление неизвестного результата сохранены | Проверить переход к приёмке и отмену |

Копирование/«Поделиться» не отправляют заказ автоматически. Сохранение заказа не изменяет складские остатки. Дополнительные native действия и сведения об истории версий сохранены; точное визуальное совпадение не подтверждено одной компиляцией.

Регрессия `PurchaseViewModelTest.formAndPlaceSavesLatestInputAndIgnoresRepeatedTap`: актуальный ввод сохраняется перед формированием; два нажатия создают один заказ. Это instrumented-тест, запуск на устройстве фиксируется отдельно от компиляции.
