Не называть merge опубликованным APK.

## Эталон и запуск

Используется config/reference.json: Web1682c88334e6fb13586ce4b530157c59ca062e43. Сервер проверяет commit и все закреплённые SHA256, обслуживает только assets исходника и собственный стенд. CSS, Manrope и SVG берутся из исходника. В HTML стенда добавлены только фиксированное время/демо-данные, фиктивный native bridge, отключение фоновой синхронизации и сбор замеров. Исходный checkout не изменяется. Эталон не является WebView-модулем Kotlin приложения.

```sh
python3 scripts/web-visual-reference.py --source ../reference --port 8765
```

Открыть http://127.0.0.1:8765 . Реестр — tools/web-reference/scenes.json, сценарии — fixture.js. Вся база демонстрационная, без реальных телефонов/токенов/ключей/копий; внешние запросы запрещены. Начальная административная сессия подменяется только внутри визуальной fixture, пароль не копируется. Native права и операции не меняются.

Ручная съёмка всех окон, без APK/signing/publish:

```sh
gh workflow run android-pr.yml --ref develop -f visual_reference=true
```

В этом режиме job checks пропускается, работает только web-reference. Обычные PR и ручной запуск без флага сохраняют прежние обязательные checks. Playwright1.56.1 закреплён lockfile; source отдельно checkout по точному SHA. Artifact web-visual-reference содержит index.html, автономный manifest.js, PNG и JSON замеров. После распаковки index.html работает со снимками без сервера; живой Web требует локальный сервер. Generated outputs не входят в Git.

## Условия сравнения

- Область приложения 1280×900 CSS px/dp; DPR/density1,25 (200dpi): PNG1600×1125. Без системных status/navigation bars; одинаковая ориентация, font scale100%, одинаковые данные и состояния.
- Светлая и тёмная тема отдельно. Проверяются границы, x/y/ширина/высота, сетка, отступы, border/radius/shadow, CSS-цвета, Manrope/weight/line-height, текст/переносы, SVG, состояния кнопок и прокрутки.
- В атласе загрузить native PNG, выбрать «Наложение» либо «Разница». Неверный размер выдаёт предупреждение; автоматическое растяжение для просмотра не доказывает совпадение. Нельзя отмечать совпадение по разным fixtures.
- Замеры получены из DOM/getComputedStyle, а не придуманы по коду Kotlin. Совпадение source-скриншота с самим собой не является тестом native. Linux Chromium PNG — воспроизводимый эталон геометрии; итоговые метрики текста, emoji/сглаживание проверяются также на одинаковом Android16 WebView/Compose. Нулевой raw pixel diff между разными растеризаторами пока не заявляется.
- Font150%, длинные имена, ошибки, disabled/loading/pressed/focus, keyboard и малый экран проверяются отдельными совместимыми состояниями после базового размера. Не ломать доступность, сохранность операций и guards ради скриншота.

## Native-only и отложенные разделы

Нет прямого Web-аналога: i/обновления и системная установка, Android permissions/SAF, запуск generation/recovery и ошибки, защитная native-копия/дополнительное подтверждение активной кассы, проверка неизвестного результата оплаты/возврата, пересчёт устаревшего заказа, отдельные native-confirmation и discard формы, preview/превышение приёмки, отдельные формы количества и фиксации инвентаризации, служебная галерея компонентов/«скоро». Их оцениваем по общим токенам и согласованному native-макету, без вымышленного Web-эталона.

Списки сотрудников/поставщиков/скидок/тарифов в Web находятся внутри настроек, состав/модификаторы — в редакторе товара; это не потерянные окна. Клиенты/согласия/лояльность06 и сайт/синхронизация/онлайн-заказы09 остаются TODO; зал/бронирования исключены. Их кнопки в исходном Web видны, но это не разрешение реализовать исключённые модули. Импорт legacy-истории/приёмочных drafts/инвентаризации по BACKUP-CORE-SCOPE остаётся TODO, их native UI для новых операций при этом существует.
