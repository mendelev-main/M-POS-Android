# Принтеры и печать

Локальная реализация09.11.2026. Статус implemented; CI/device-verified не заявлены. D01–D03 реализованы в описанных ниже границах. D04/Telegram не входит в задачу. D05 — бумажные образцы и физическое оборудование — pending.

## Источник

Зафиксированные `network-printer.js`, `print/MPosReceiptLayout.kt`, `print/EscPosPrinter.kt`, `CashDrawerCommand.kt`, Web `payment.js`, `parked-orders.js`, `shifts.js`. Геометрия графического документа перенесена в Kotlin:384/576 точек, поля14/24, колонки55/43%, разделитель, размеры обычного/кухонного текста. Нет JS/WebView runtime. Исходный Web-пароль/сетевые токены не переносятся.

## Пользовательский путь

Панель администратора → Сетевые настройки → Подключить принтер. Модальное окно: название/IPv4, бумага58/80мм, платежные/кухонные чеки, комментарии, заголовок и касса, фразы, галочки категорий, автопечать, копии, ящик и технические параметры. Сохранение обновляет device-local список; нажатие строки открывает редактирование, удаление подтверждается. Только одна конфигурация управляет ящиком; включение другой выключает предыдущую с повышением revision. Конфликт устаревшей формы не перезаписывает настройки.

«Проверить связь» открывает TCP-соединение без печати. «Пробная печать» сначала сохраняет конфигурацию, затем отправляет тест; включённый ящик получает отдельный импульс. Неподтверждённое сохранение не запускает тест. «Вид чека» показывает графический тестовый образец; окно печати реального документа показывает содержимое конкретного чека. Сохранённая конфигурация не объявляется подтверждённым подключением к оборудованию.

## Документы и команды

| Сценарий | Поведение |
|---|---|
| Успешная оплата | Автопечать по флагам принтеров после получения сохранённого receipt; наличная часть больше нуля открывает ящик |
| История / результат оплаты | Выбор принтера, предпросмотр, явная повторная печать без повторной оплаты |
| Текущий заказ → три точки | Счёт «НЕ ОПЛАЧЕН» или заказ кухни; финансовые данные не сохраняются печатью |
| Отложить / переключиться с сохранением текущего | После сохранения отложенного заказа кухня получает только положительную разницу количества относительно предыдущего снимка |
| Оплата ранее отложенного | Уже запланированная кухня повторно не печатается; платёжный чек печатается |
| Кухня | Крупные название/количество, модификаторы и комментарии, фильтр категорий; без цен |
| Платёжный чек | Исторические суммы строк, скидки, доставка, модификаторы, комментарии по флагу, наличные/карта/части, внесено/сдача, дата/номер, сотрудник из сохранённой смены |
| Закрытие смены | Автоматический отчёт после сохранения; ручной отчёт из истории смен через предпросмотр |
| Ящик | Один принтер, валидная ESC p-команда; открытие смены/начала пересчёта, сохранённые внесения/изъятия, наличная продажа/возврат, явное ручное открытие в смене/администрировании |

## Хранение и сбои

Сетевой транспорт — TCP9100 с таймаутом подключения5с и принудительным закрытием сокета через15с, включая зависшую запись. Команды каждого IP выполняются последовательно; разные IP независимы. Графический ESC/POS GS v0 сохраняет кириллицу без зависимости от кодовой таблицы. Опциональный текстовый режим использует CP866/ESC t17; его поддержка зависит от модели принтера. DPI сохраняется как параметр совместимости: как в исходном Android raster, геометрия определяется шириной в точках, а не DPI. Команды init/cut берутся из конфигурации.

Денежные суммы — сохранённые копейки/BigDecimal, без Double-пересчёта продажи. Ширина/высота и измерение текста — графические числа. Повторная печать не вызывает SaleRepository.commit, движения склада или кассы. Ошибка печати не отменяет сохранённую продажу.

Перед сетевой отправкой сохраняется claim задания в noBackupFilesDir. Идентификаторы автоматических заданий стабильны по receipt/shift/printer/copy; при повторном открытии результата они не отправляются снова. Отправка/сбой записи статуса/обрыв сети могут дать неопределённый результат: автоматического повтора нет, пользователь сначала проверяет бумагу и явно запускает повторную печать. Процесс, завершившийся после claim и до отправки, также требует ручной проверки. Это at-most-once dispatch, не гарантия физической выдачи чека. Перезапуск не восстанавливает очередь в фоне и не запускает принтер без пользовательского рабочего сценария.

Журнал кухни сохраняет точные количества по cart session/line/printer перед отправкой. Уменьшения не печатаются; положительные добавки печатаются без потери дробной точности. В отличие от Web threshold0.0001, native не теряет меньшие допустимые количества. Сбой после записи снимка требует явной ручной печати. Нет автоматической печати удалений/сторно кухни — этого нет и в рассмотренном Web-сценарии.

Конфигурации и print-claims относятся к устройству, не меняют Room schema и не входят в существующий backup/import Web. Их перенос — отдельный TODO. Принтеры онлайн-заказов/лояльность зависят от ранее отложенных модулей06/09. Bluetooth/USB не входят в LAN-контракт исходника.

## Проверки и оставшаяся приёмка

`PrintingTest`: сохранённые суммы/смешанная оплата, bill, кухня/категории, точная delta, routing/auto/cash, ESC p, неизвестный исход, ошибка claim/render/status без второй отправки. `PrinterConfigurationTest`: валидация. `PrinterSettingsStoreTest`: перезапуск/edit/stale/admin/delete/corruption и единственный ящик. `PrinterRenderingTest`: настоящий Bitmap/raster58/80 и перезапуск durable claims с fake transport. Instrumented-тесты отдельно от JVM/компиляции; запуск на устройстве фиксируется в build-log.

Для D05 владелец проверяет на своём принтере:58/80мм, кириллицу/длинные названия, модификаторы/скидки, смешанную оплату и сдачу, счёт/кухню, фильтр категорий, повторное откладывание с добавками, перезапуск, отключённую сеть, отрезку, количество копий и ящик. Сверка бумажных образцов с Web обязательна до утверждения физического совпадения.

Для target36 используется существующее INTERNET; локальная защита Android16 по умолчанию opt-in. При повышении targetSDK требуется отдельная проверка runtime-разрешений LAN по [документации Android](https://developer.android.com/privacy-and-security/local-network-permission). Автоматического поиска принтеров в LAN нет: адрес вводится вручную, как в Web.
