Сменный отчёт отправлять после каждой сохранённой закрытой смены независимо от группового отчёта; месячный — после каждого закрытия в последний календарный день месяца, с актуальными итогами месяца на момент закрытия. Это правило явно подтверждено владельцем. Ключ месячной доставки включает месяц и ID закрываемой смены; новый снимок после следующего закрытия не подавляется как дубль. Ошибка одного получателя не блокирует другого и не откатывает смену.

Структура: период/смена, выручка/количества/чеки, динамика против прошлого сравнимого периода, почасовой график с пиком, доли категорий, лидеры товаров и краткие вычисляемые выводы. Без демонстрационных чисел и вымышленных сравнений. Валюта BYN, разные единицы количества отдельно. Продажи/возвраты по принятым native правилам; исторические категории из receipt payload.

## Реализованный сценарий

В Telegram-настройках добавлены два независимых переключателя; при включённом Telegram выбранная отправка требует корректного ownerChatId. Старые encrypted settings v1 читаются с обоими новыми флагами false. Токен/ID используют прежнее защищённое хранение, сами аналитические изображения не записываются в production-файлы. Для владельца создаётся отдельный recipient: ownerChatId вместо группы, threadId пустой. Выключенное уведомление группы или его отказ не подавляют владельца. Ошибка подготовки одного вида статистики не подавляет другой.

Автоматика вызывается после подтверждённого сохранения закрытия смены. Сменная статистика относится к конкретной закрытой смене, включая возвраты, оформленные именно в ней. Месячная — события с начала календарного месяца по timestamp закрытия включительно. Последний день проверяется по сохранённой зоне смены, не по времени запоздавшей доставки. Поэтому два закрытия в последний день создают два разных месячных снимка; поздние события не попадают задним числом в первый отчёт.

Отчёты читаются одной read transaction. Для смены выбираются чеки/возвраты только двух сравниваемых смен; для месяца — ограниченный SQL-диапазон текущего/прошлого месяца плюс исходные чеки возвратов. Каталог в рабочем состоянии не используется: названия, категории, количества и себестоимость берутся из immutable receipt snapshots. Проверяются суммы и fingerprint исходного чека возврата. Чтение не меняет кассу, остатки, чеки и смены; подтверждение отправки не вызывает финансовых команд.

## Актуальные подпись и минималистичный макет

Уточнение владельца09.11.2026: подпись владельцу теперь содержит только метаданные закрытой смены:

```
🧾 Смена: №184
🟢 Открыта: 09.11.2026 08:00
🔴 Закрыта: 09.11.2026 22:00
👤 Сотрудник: Бондарева А.А.
```

Номер вычисляется тем же ShiftDashboardRules.numbers, что используется историей смен; это не UUID. Времена форматируются в сохранённой зоне смены. В подписи ФИО сокращается до фамилии и инициалов и экранируется для HTML; имя в базе не меняется. Заголовка «Коммерческая аналитика» и счётчика страниц в подписи нет. Для месячного отчёта дополнительно указано «Месяц: MM.yyyy», чтобы отличать два отчёта.

Изображение1080px сохраняет тёмную палитру, но содержит только:
- четыре равные карточки в сетке2×2: выручка, прибыль, чеков, возвраты в деньгах;
- продажи категорий: название, доля и сумма BYN;
- продажи позиций: название, доля и сумма BYN.

Выручка = продажи минус возвраты, прибыль = выручка минус историческая себестоимость нетто и доставка нетто. Чеков — количество новых продаж, возвраты его не уменьшают. Проценты категорий и позиций — доли продаж товаров после скидок, без доставки, с точностью до0,1% и распределением остатка до100%. Возвраты выделены отдельной денежной карточкой; они не превращаются в отрицательные доли. Строки, у которых в периоде были только возвраты без продаж, из списков продаж исключены; нулевые по цене реальные продажи остаются.

Убраны почасовой график, сравнения/динамика, количества/единицы, средний чек, подробности возвратов, инсайты и длинные объяснения. Для этих изображений больше не читается предыдущая смена/месяц. Исторические данные и точность денежных расчётов сохранены. Остались одна краткая подпись базы процентов и обязательное предупреждение, если архивная Web-история не включена в native-учёт.

Первая страница содержит восемь категорий с агрегатом «Остальные» и восемь позиций; остальные данные без усечения продолжаются на следующих страницах по24строки. Пустые периоды показывают нули и «Нет продаж». Длинные названия/суммы переносятся. Альбом/PDF по-прежнему объединяет весь отчёт в одну отправку.

## Предпросмотр, повтор и границы

В настройках доступны предпросмотры смены и месяца без токена и отправки. Они используют последнюю закрытую смену; месячный предпросмотр разрешён и до последнего дня, срез подписан. Это не включает месячную автоматическую отправку вне последнего дня. Для предпросмотра нужен административный доступ. «Повторить статистику владельцу» — явная отправка по сохранённым настройкам; новые manual-ключи допускают осознанный повтор после проверки чата.

Автоматический ключ теперь один на весь отчёт: вид/месяц/closing shift ID/получатель, namespace bundle:v2. Сохраняются sending/sent/unknown правила TelegramDelivery: повтор закрытия не дублирует весь пакет; неопределённый результат не повторяется вслепую и не дробится на повторные отправки страниц. Старые per-page markers проверяются перед автоматической отправкой нового формата: ранее обработанный отчёт не пересылается альбомом без явного ручного повтора. При остановке процесса до постановки задания возможна ручная отправка; это не гарантированная фоновая очередь. Снимок повторной ручной отправки читается заново из текущей сохранённой базы, поэтому восстановление другой базы — отдельная операция.

Backend для этого функционала не нужен и не подключался. Продуктовый PDF служит визуальным референсом, а не инструкцией к финансовой логике.

Telegram ограничивает альбом2–10элементами: [официальный контракт](https://core.telegram.org/bots/api#sendmediagroup). Альбом визуально сгруппирован в чате, хотя API возвращает Message для каждого элемента. Сменный и месячный отчёты остаются разными отчётами.

PDF рисуется теми же Canvas-компонентами непосредственно в PdfDocument, без накопления Bitmap всех страниц в памяти. Страницы не удаляются и не отправляются вторым альбомом. При превышении50MB или ошибке подготовки отправка не разбивается молча; возвращается отказ. Предпросмотр по страницам сохранён, он ничего не отправляет.
