## Критический путь и зависимости

05c.1→05c.2→05d→07a→07b→08. Этапы06 и09 не являются текущими зависимостями. Отчёты читают продажи/кассу/склад; export использует готовый snapshot отчёта. Backup охватывает реализованные модели01–05 и фото; обычные Room migrations тестируются при каждом изменении схемы уже сейчас. Обработка отложенных Web полей в импорте требует явного preview/политики, без молчаливого удаления. Remote loyalty/сайт/transport/binding не начинаются в рамках текущей очереди.

В M01/M02/M03/M04/M05/M06 остаётся поперечная работа: lifecycle/adaptive UI, файлы/backup, coordination/outbox/сеть/секреты. Это развивается вместе с нужным продуктовым сценарием, не десятки пустых Gradle modules заранее.

## Проверки и выпуск

Каждый инкремент: pinned Web feature+Android adapter+regression → короткий контракт/примеры → domain/Room → shared UI → meaningful tests → preflight/diff → нужные JVM/API36/upgrade проверки → evidence в harness/context, build-log и PARITY. Новые деньги/склад требуют rollback/replay/race/restart; docs-only не требуют полного эмулятора.

Работа идёт в develop. Маленькие коммиты не публикуются как обновления. Готовый крупный блок проходит сверку и по запросу владельца PR develop→main; после merge выполняется подписанная сборка/публикация стабильного APK и проверка production upgrade. App ID/ключ подписи неизменны. Отдельная ветка release сейчас не нужна. Текущая задача не разрешает новый выпуск автоматически.

Решение владельца перед05c.1 (2026-10-30): продажа100 BYN30октября остаётся +100 в дне продажи; возврат31октября отражается −100 в дне возврата; общий период даёт0. Не исключать исходный чек из прошлого периода задним числом. Это явное отличие от pinned Web analyticsData. Остальные определения метрик/доставки/среднего чека закрепляются в контракте05c.1; код отчётов этим решением автоматически не добавлен.

Перед эксплуатацией: физический Android16 планшет (ориентация/клавиатура/picker/шрифт/тёмная тема/установка), бизнес-сверка с Web на утверждённых примерах, backup/recovery, реальные интеграции только на согласованной среде, измерение больших данных и история обновления подписанного приложения. Конкретную длительность или процент готовности нельзя вывести из количества документов; оценка даётся по согласованному scope и результатам каждого блока.
