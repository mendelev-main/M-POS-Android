# 07.3b — применение native-копии и startup recovery

Статус: AC01–AC06 implemented/validation pending. Native format1/schema9. Web JSON conversion07.4/activation07.5 не входят. Stable main/signing/applicationId и Room schema не меняются.

## Выбранный durable протокол

Рабочая БД не заменяется за спиной Room. `native-activation/generations/<uuid>` содержит отдельную рабочую SQLite базу и `product-photos`; `generation.json` связывает source/target fingerprints и IDs подготовки/защиты. Готовый каталог без active pointer не имеет authority. `active.json` — единственный authoritative selector, AtomicFile+fsync parent; старый или новый pointer после interrupted write, не несколько переименований БД+фото. Legacy — прежние databases/mpos.db и files/product-photos. Нет переноса preferences/updater/signature/admin state.

AppDataset выбирает paths один раз на процесс. CatalogDatabase.get и ProductPhotoStore(filesDir) используют один pinned набор. После commit pointer текущий процесс остаётся на OLD пути и не открывает новую базу/фото. Обязательное закрытие M-POS и новый запуск создают новый Room/Coil/формы и снимают старую власть InventoryRuntime baseline. Нельзя освободить старый процесс одной activity recreation. Закрытие — явная кнопка, никакой скрытой оплаты/HTTP/печати.

## AC01–AC06

- AC01: structural native checks07.2 + отдельная проверка против свежей ожидаемой Room9 по public SQLite metadata (columns/defaults/PK/FK/index columns/uniqueness/collation/order/partial), а не доверие одному identity_hash. Table/view/trigger allowlist; дополнительные неподдерживаемые DDL constraints/выражения отказываются. Проверяемые строки читаются READONLY SQLite вместе с committed WAL и копируются typed bindings в отдельную свежую trusted schema; source DDL не исполняется и live main-file без WAL не используется. Room restricted implementation API не используется; первоначальная локальная попытка TableInfo.read остановлена lint RestrictedApi, заменена собственным PRAGMA comparison без подавления lint.
- AC02: strict JSON/no duplicate keys/integer numeric fields, supported document namespaces/codecs, catalog/units/recipe DAG/modifiers, historical receipt frozen quote/payment/consumption and SQL headers/result refs, refund history, shifts/cash, current+parked и split context/cart/revisions/paid command results. Legacy pre-payment cart v1 без checkout/split/parked сохраняется и мигрирует обычным initialize при первом открытии workspace, без синтеза paid facts. Незавершённый editor/unpaid form не пересчитывается по текущим ценам. Исторические unit=null остаются unknown; source payloads не переписываются. Неактивная authority инвентаризации теряется через новый процесс, проведённые фиксации сохраняются. Никакого JS runtime/Double/внешнего транспорта.
- AC03: явный confirm полной замены; если protection содержит active shift/partials/unknown payment activity — отдельный active checkbox и backend flag. Перед заморозкой в одном target Room transaction снова снят coherent snapshot и fingerprint сравнён с verified protection. Изменение target→staleTarget, нужен новый prepare/preview. Source pending session/command, уже завершённый чеком в target,→paymentProvenance отказ до заморозки, чтобы не принять остаток второй раз. Полная замена source40/target30 разрешена при корректных независимых фактах, не merge.
- AC04: source generation полностью подготовлена, synced и fingerprint-verified до freezing. Financial installer mutex + admin authorization + target Room transaction сериализуют финальное сравнение. Durable pending.json записан ДО freeze. В той же target transaction устанавливаются permanent BEFORE INSERT/UPDATE/DELETE abort triggers на все17business tables. Они закрывают также незагейтенные workspace/initialize/cleanup/direct DAO writes на всех SQLite connections; Room business rows не переписываются. После commit seals старые writers отказываются, старый UI закрывает runtime gate, installer mutex остаётся заблокированным до выхода процесса. Atomic pointer publication выбирает новый dataset для следующего процесса. Фото namespace отдельный; никакого overwrite старых immutable IDs.
- AC05: MainActivity запускает recovery ДО FoundationScreen/repositories. Pending из того же процесса→restart required; новый процесс сверяет authoritative pointer и hashes/fingerprints/schema/domain/photos. Если pointer NEW — только проверенный NEW; если OLD с полным seal — проверка exact frozen OLD, затем убрать только наши seals. Если freeze transaction откатилась (0seals), старые уже стоявшие в очереди команды могли завершиться в OLD; сохраняем эти факты и валидируем OLD, не откатываем его слепо к protection. Неполный seal/неизвестный pointer/corrupt descriptor/несходящийся committed dataset→blocked recovery, файлы не удаляются и legacy молча не открывается. Ready journal очищается durably ДО допуска рабочих операций. После первого successful startup обычные новые изменения не сравниваются с bootstrap fingerprint при каждом запуске. Fresh recovery закрывает administrative access. Initializing readers не запускаются за startup gate.
- AC06: shared confirmation window/active acknowledgement/error wording, old dialog cannot borrow fresh login. Activity/SavedStateHandle bundles помечаются dataset generation: другой набор (включая pre-generation bundle при NEW pointer) отбрасывается до super.onCreate/onRestoreInstanceState, обычная recreation в том же наборе сохраняется. Runtime root не показывает кассовую навигацию, пока нужен новый запуск. Inventory позволяет заново подготовить опубликованную protective copy; при этом создаётся новая защита нынешнего target. Prepared IDs/record hashes проверяются заново, unknown outcome требует startup reconciliation. UI clear не удаляет durable файлы.

## Checkpoints и наблюдаемая приёмка

sourceValidated/generationPrepared/targetRechecked/journalWritten/sealInstalled/oldFrozen/pointerPublished. До pointer commit выбирается OLD; после — NEW. При rollback freeze возможные поздние OLD commits сохраняются как OLD, не смешиваются с NEW. Новые generations без pointer не активируются; protection/source original сохраняются. Corrupt committed file/pointer блокирует startup, без destructive fallback.

NativeActivationTest: independent data40/30, all checkpoint reopen, blocked raw DAO and initialize, exact remaining payment/replay/change/net cash/stock0.0004, stale target/extra confirmation, forged Room hash/schema and payment mismatch, lost acknowledgement, corrupt pointer/new generation. Process driver после прежнего APK-update suite на свежем emulator debug install: explicit instrumentation fixture seeds/applies, проверяет pinned OLD paths/seal/same-process gate; force-stop→обычный MainActivity startup NEW+photos/admin locked; следующий настоящий instrumentation process проверяет source40, защиту30, completion60 ровно один раз, change10/cash+40 и stock9.0004. Test fixture находится только в androidTest, release APK не содержит mode hook. Driver проверяет emulator hardware/API36 до uninstall и не обращается к production устройствам/сети. Физическое power-loss/disk-full/большие данные/OEM/150% ещё отдельная приёмка; callback faults и force-stop их не заменяют.

## Ограничения текущего контракта

Поддерживается native schema9/format1, не downgrade будущих схем. Domain validation опирается на действующие native codecs и immutable facts; непонятные версии/связи отказываются, не превращаются в пустую историю. Native snapshots с неизвестными legacy финансовыми фактами требуют отдельного compatibility profile. Полный Web migration остаётся07.4; source.Web payment privacy/loyalty/online несогласованные факты автоматически не активируются. Retention/paging/staging cleanup не удаляют защитные копии автоматически и остаются отдельной maintenance-задачей.
