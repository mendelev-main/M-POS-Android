Плитки категорий/товаров, поиск, одноуровневые папки и порядок, отдельный явный режим раскладки; persistent current cart, количество/удаление/очистка, модификаторы, ручная цена. Оплаты, parked transfer02b, явное revalidation сравнение02c, параметры доставки/клиента будущих модулей не вводятся в этой части. Физическая приёмка отложена владельцем2026-10-24 и не блокирует02a.

Источник pinned1682c883: pos-navigation.js, cart-composition.js + android-pos-stock.js/android-safety.js; regressions source-product-stock.test.cjs (navigation persist/reorder/folder delete/fault, same modifiers merge, manual price, shared ingredient shortage/decrease). Внешний вид: pos.html product-grid/pcard/cart и DESIGN-SYSTEM, shared Manrope/buttons/dialogs. Папка открывается общим широким dialog; настройка папки — обычным. Native доступная альтернатива drag: явные «Раньше/Позже» и выбор папки; произвольные пустые grid slots/drag остаются последующей частью W01, не заявлять полный visual/layout parity.

Native уточнения: ручная цена >0 с максимум2decimal вместо Web silent cent rounding; одинаковая ручная цена/набор options объединяются согласно утверждённому native contract (Web manual строки не объединяет). Ключ: productId+configuration revisions+canonical selected options+manual/base price. Количество базовых продажных единиц >0/max999999999.999999999 (9decimal); плюс/минус по1, минус до0 удаляет, прямой0/invalid не удаляет. До03 суммы только exact decimal preview, без финансового rounding/оплаты.

Room schema5: workspace_documents PK(id),revision,payload; независимые versioned JSON документы layout/current, одна база с каталогом/result/audit. Неизвестная payload version — явная ошибка, не reset. Layout normalizes live category/product references: новые товары append, сменившие категорию возвращаются в её root; folder delete возвращает товары в root. Сохранение с expected layout revision. Product/category delete guards учитывают сохранённую раскладку и cart references. Snapshot recipes и выбранных options в current сохраняет точный расход после изменения каталога; active dependencies не удаляются.

Add/step — delta intents с commandId, сериализованы transaction/read-latest; rapid taps не используют устаревший absolute quantity. Set quantity/Clear и layout используют expectedRevision. fingerprint/result/audit в одной transaction; injected failure после документа откатывает всё. UI публикует committed state. Snapshot зависимостей/revisions определяет stale строки после catalog edit/restart; increase/add блокируются до удаления/пересчёта, decrease/remove/clear разрешены. 02c добавит явный пересчёт с разницей, сейчас доступно удалить устаревшую строку и добавить снова.

RecipeCalculator агрегирует запросы всех строк по snapshot graph до decimal scale12; не умножать округлённый per-unit расход. Current reserve — derived projection из сохранённой корзины, ledger не меняется. При increase/add проверяется полный кандидат против текущих balances и per-simple flags. При decrease/remove не блокировать исправление дефицитного заказа. Parked резервов пока нет; они добавляются02b в ту же transaction boundary.
