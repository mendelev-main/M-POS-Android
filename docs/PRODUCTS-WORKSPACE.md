# Первые два этапа: требования

Подробные сценарии, native решения и последовательность инкрементов: [CATALOG-WORKSPACE-SPEC.md](CATALOG-WORKSPACE-SPEC.md). Контракты команд и fixtures: [IMPLEMENTATION-CONTRACTS.md](IMPLEMENTATION-CONTRACTS.md). Все P/W пока planned.

## 01 — товары

| ID | Сценарий и ожидаемый результат |
|---|---|
| P01 | Создать/редактировать простой товар: название, категория, цена, себестоимость; пустое имя и некорректное число отклоняются, введённая форма сохраняется при ошибке |
| P02 | Поиск по имени/категории с нормализацией регистра/ё/пробелов, фильтр категории; пустой список и отсутствие результатов различимы |
| P03 | Категории: создание/переименование/порядок; удаление используемой категории требует явной политики, не теряет товары |
| P04 | Базовая и отображаемая единицы, минимальный остаток, упаковка закупки; кг↔г/л↔мл без изменения физического запаса; недопустимые пары отклоняются |
| P05 | Состав и выход рецепта, вложенные ингредиенты; вычисляемая себестоимость, защита циклов/удалённой ссылки, запрет изменения типа связанных товаров |
| P06 | Модификаторы: min/max, варианты существующих товаров, qty>0, доплата; дубль/ссылка на себя/невыполнимый минимум отклоняются |
| P07 | noStockTracking и allowNegativeStock независимы, только simple; поведение по docs/DATA.md |
| P08 | Добавить/заменить/удалить фото через picker, отказ доступа/ошибка записи не портит карточку; перезапуск сохраняет фото и товар |
| P09 | Удаление/архивирование используемого товара не ломает рецепт/историю; конкретную политику зафиксировать до реализации |
| P10 | Прямая правка остатка в карточке без обязательной причины сохраняет ledger delta; concurrent stock change даёт Conflict. Данные после process death/restart; отказ записи не показывает успех; Room migrations проверены с первого изменения схемы |

Web CSV import исследован, но в исходном UI кнопка скрыта; включать в native после отдельного решения, не как обязательное действие 01. Точные ограничения полей и форматы фиксировать при реализации по указанному срезу, не по памяти.

## 02 — рабочая зона

| ID | Сценарий и ожидаемый результат |
|---|---|
| W01 | Плитки, категории/папки, поиск и порядок; настройки раскладки сохраняются; Compose layout на планшете в landscape/portrait |
| W02 | Добавить товар, настроить модификаторы/ручную цену если требуется, изменить количество/удалить строку; одинаковые настройки объединяются, разные не теряются |
| W03 | Остаток/дефицит на плитках учитывает recipe/modifiers и все резервы; 0.4 г расхода не превращаются в ноль |
| W04 | Текущий заказ и отложенные чеки: сохранить, открыть, заменить/вернуть, удалить с понятным подтверждением; дважды не резервировать |
| W05 | Очистить текущий чек с подтверждением, отказ записи сохраняет корзину; отдельные поля настроек заказа не исчезают случайно |
| W06 | Черновик переживает restart/process death; смена ориентации не добавляет строк и не теряет выбор; быстрые повторные нажатия согласованы |
| W07 | Состояния loading/empty/error, клавиатура чисел/текста, доступные подписи, крупные touch targets; проверка на реальном планшете |

В 02 расчёты корзины доступны как preview, без записи продажи и ложной кнопки «оплачено». Изменения рецептуры при активном черновике требуют явной revalidation; политика snapshots/пересчёта фиксируется тестом. Формальная оплата и исторические stock snapshots входят в 03.
