# Каталог и рабочая зона: спецификация 01/02

Статус: planned. Источник: pinned Web из [SOURCE.md](SOURCE.md). Native решения обозначены явно; это контракт для реализации, а не отчёт о готовом UI.

## Наблюдения по исходникам

| Источник в `app/src/main/assets/pos/Web/js/features/` | Подтверждённое чтением правило |
|---|---|
| `product-persistence.js: saveProduct` | имя обязательно; состав непустой, выход >0; оба складских флага только simple; проверяется изменение записи за время сохранения |
| `product-configuration.js: componentBaseQty / convertProductQty / validateModifierGroups` | положительный расход, совместимые единицы; группа имеет имя/варианты, существующие ссылки, запрет себя/дубля, qty>0 |
| `product-categories.js: saveCategory / deleteCategory` | имя обязательно, регистронезависимый дубль запрещён; переименование затрагивает ссылки; используемая категория не удаляется |
| `product-editor.js: requestCloseProductEditor / productEditorDirty` | редактор отслеживает несохранённые изменения; показывает использование товара |
| `cart-composition.js: productNeedsManualPrice / modifierSelectionSignature` | цена ≤0/нечисловая требует ручного ввода; конфигурация модификаторов участвует в различении строк |
| `parked-orders.js: parkOrderNow` | отложенный заказ хранит строки, подпись, тип, клиента, комментарий, доставку/источник; сохранение заказа и очистка текущего атомарны |

## 01: список и карточка товара — P01/P02/P10

Список: строка поиска, категория, название/тип, продажная цена, единица и состояние фото. Вход в карточку по стабильному productId. В пустой базе доступно создание; при нулевом результате поиска — сброс фильтра. Поиск нормализует регистр, ё/е и повторные пробелы (native требование P02); поиск не изменяет сохранённое название.

Поля нового простого товара: название, категория (необязательная), цена продажи, себестоимость, базовая/отображаемая единицы, минимальный остаток, закупочная упаковка, noStockTracking, allowNegativeStock, символ/фото. Цена 0 — товар с ручной ценой в 02, не бесплатная продажа по умолчанию. Отрицательную цену/себестоимость и некорректную числовую строку отклоняем (native решение: не повторять `parseFloat(...) || 0` из Web). Отдельное правило бесплатной позиции/подарка относится к 03/06.

Не вводить произвольные ограничения длины/точности молча: до UI-кода закрепить лимиты и сообщения в field validation fixtures. Одинаковое название товара допускается при разных ID; категория имеет уникальный нормализованный ключ. Валюта и границы финансового округления не определяются формой каталога, см. открытые решения 03.

Создание → validate → одна Room transaction → success/возврат в список. Повтор сохранения использует draftId/commandId, не создаёт дубль. Редактирование передаёт expectedRevision; конфликт оставляет форму и предлагает перечитать запись. Изменение типа связанных/имеющих складские единицы товаров запрещаем, вместо него — новый товар. Ошибка БД оставляет сохранённую версию и редактируемый черновик.

Несохранённый редактор переживает rotation; после process death восстанавливается отдельный draft, не выдаваемый за сохранённый товар. Отбросить — явное действие. Поведение draft отличается от committed catalog и проверяется отдельно от P10 persistence.

## Категории и удаление — P03/P09

Категория: ID, имя, порядок, цвет/символ. Native решение: ссылки по ID; переименование не меняет productId/categoryId и сохраняет раскладку. Пустая категория удаляется с подтверждением; используемая блокируется со списком зависимостей. Чтобы удалить, сначала перенести товары в другую/«Без категории» одной явной командой; автоматического переноса нет.

До отдельного согласования физическое удаление товара разрешено только при отсутствии рецептур, модификаторов, раскладки, черновиков, складской и продажной истории. Иначе команда отклоняется с объяснением. Архивирование — отдельное будущее действие с правилами активных заказов; не подменять им незаметно кнопку удаления. Исторические документы никогда не удаляются каскадом вместе с товаром.

## Единицы и начальный остаток — P04/P07

Базовая единица определяет хранение; отображаемая — только ввод/показ совместимой размерности. 1 кг отображается как 1000 г, физический запас не меняется; цена продажи от display unit не пересчитывается. Смена размерности при наличии движения/ссылок запрещена. Упаковка «коробка 12 × 0.5 л» хранит явный коэффициент в базовую единицу; пустой коэффициент не заменяется единицей автоматически при приёмке.

Native решение для 01: начальный остаток нового simple создаётся отдельным opening movement в той же transaction, причина «Начальный остаток». До 04 редактирование карточки не перезаписывает имеющийся запас; корректировки входят в складской документ 04. Это намеренное отличие от поля stock в Web saveProduct и защита будущей истории. Отрицательный старт разрешён только при allowNegativeStock; noStockTracking не уничтожает уже существующую историю.

noStockTracking исключает конкретный simple из ограничений/движений; allowNegativeStock разрешает реальный отрицательный баланс конкретного simple. Оба флага независимы. Composite не получает собственный баланс. Переключение флагов не корректирует остаток задним числом.

## Состав — P05

Редактор выбирает существующий товар-компонент, положительное количество и совместимую единицу. Сохраняются recipeYield>0 и единица выхода; себестоимость вычисляется из стоимости компонентов с нормированием на выход, не вводится как остаток composite. Вложенные составы разворачиваются до простых товаров с проверкой полного графа на цикл, отсутствующую ссылку и несовместимую размерность.

Пример: выход 10 шт, мука 1 кг → одна продажная единица требует 0.1 кг муки; две — 0.2 кг. Новая редакция состава меняет будущий preview, но не старые receipt/stock snapshots. Для активного черновика используется revalidation из раздела 02.

## Модификаторы и фото — P06/P08

Группа: стабильный ID, название, min/max выбранных вариантов; вариант: ID, существующий productId, подпись POS, qty>0, priceDelta decimal. Требование native: проверять исходные min/max до нормализации; невыполнимый минимум/дубли/ссылка на себя отклоняются, а не исправляются молча. Отрицательная priceDelta допустима только при неотрицательной итоговой цене конфигурации; финансовые скидки отдельны.

Фото выбирается системным picker, копируется в private staging с проверкой читаемости/формата/размера. Лимиты фиксируются до подключения обработки изображений. После подготовки файла transaction заменяет photoId. Старое фото удаляется только после commit и отсутствия ссылок; orphan staging очищается отдельно. Ошибка/отмена picker сохраняет прежний товар/фото, restart не зависит от временного URI. Upload на сайт в 01 не запускается.

## 02: рабочий экран — W01/W02/W07

Плитки показывают название, фото/символ, цену или «Ввести цену», доступность/дефицит. Поиск не меняет состав корзины. Папка раскладки и товарная категория — разные сущности; перестановка/перемещение сохраняются командой layout с revision. Во время продажи отсутствует случайное включение режима редактирования.

Добавление: выбор товара → выбор обязательных модификаторов → ручная цена при необходимости → проверка доступности → commit черновика → новая корзина. Отмена любого диалога не добавляет строку. Native ключ объединения включает productId, канонический набор optionId/qty/priceDelta, ручную цену и версию конфигурации. Один набор в разном порядке объединяется; разные цены/варианты остаются отдельными строками. lineId стабилен при изменении qty; отображаемое имя не служит ключом.

Количество строго >0. Действие «−» при достижении нуля удаляет строку согласно явно показанному UI; прямой невалидный ввод не очищает строку. Каждый плюс/минус сериализуется; быстрые нажатия не теряют шаги. Сумма/доступность публикуются из committed session, не до подтверждения БД. Свайп не является единственным способом удалить строку.

## Доступность и черновики — W03/W04/W05/W06

Domain разворачивает recipes/modifiers и учитывает все current/parked reservations. При редактировании заказа исключает его старый reserve, затем проверяет полный кандидат; при park/unpark резерв переносится, не добавляется второй раз. Фактического складского списания в 02 нет. noStockTracking/allowNegativeStock применяются к каждому простому ингредиенту.

Сессия хранит строки с revision/configuration snapshot, тип заказа (на месте/с собой/доставка), подпись, комментарий и доступные поля доставки. Клиент/подарок/WEB появляются в своих этапах; сохранение уже известных полей не должно их обнулять. Изменение типа доставки не оставляет скрытый сбор в сумме.

Отложить непустой заказ: запросить подпись при её отсутствии → transaction переносит current в parked и создаёт пустой current. Открыть parked при непустом current: предложить сначала отложить текущий либо отменить; молчаливой замены нет (native решение). Пустой current заменяется parked атомарно с удалением прежнего parked слота. Удалить parked/очистить current — подтверждение; ошибка сохраняет прежние записи и резервы.

Если товар/рецепт/цена изменились вне черновика, revision mismatch помечает строки «Требуется проверка». Черновик сохраняет прежний preview, но не может стать оплаченной продажей до явного пересчёта с показом изменения суммы/состава и повторной проверкой доступности. В 02 кнопки оплаты нет; в 03 этот барьер обязателен. Удалённая ссылка не заменяется нулевой ценой/нулевым расходом.
