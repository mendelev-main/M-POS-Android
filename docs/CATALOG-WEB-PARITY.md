# Вкладка «Товары»: Web → native

Локальный перенос, обновлено 2026-11-08. Источник: закреплённые product-catalog.js, product-categories.js, product-editor.js, product-configuration.js, product-persistence.js и CSS pos.html. Просмотрены T01-light.png и измерения T01; ранее просмотрены карточки T03/T04. mpos-phase/mpos-domain. Работа в текущем main локально, публикация только отдельной командой владельца.

## Подключённые сценарии

- P01/P02: заголовок с общим количеством, поиск в строке с очисткой, горизонтальные категории из используемых товаров, таблица «Товар / Категория / Тип / Цена / Себестоимость / Остаток». Количество в заголовке не меняется при фильтрации. Категории и поиск применяются совместно; удалённая/исчезнувшая категория возвращает «Все». Пустой каталог отличается от отсутствия результатов. Поиск NFC/русский регистр/ё→е/нормализация пробелов по Web, сортировка русская с числовыми фрагментами (2 раньше 10).
- P03: список категорий с цветом и количеством товаров, добавление, изменение имени/обозначения/цвета, отмена, подтверждение удаления. Переименование сохраняет ID и связи товаров. Категорию с товарами удалить нельзя. Нативное изменение порядка сохранено в меню долгого нажатия на строку («Выше / Ниже»), чтобы не добавлять лишние видимые кнопки в Web-список.
- P01/P04–P08/P10: переход из строки в действующий полноэкранный редактор, создание/редактирование, цена/себестоимость, состав/единицы/выход, остатки/флаги/порог/закупочная упаковка, фото, модификаторы. Существующие write use cases и проверки рецептур/остатков сохранены. Артикул, внутренняя заметка и обозначение теперь редактируются и сохраняются, больше не placeholder.
- Выбор ингредиента и товара модификатора открывает окно с поиском, прокручиваемым списком и категориями/единицами в подписях; отмена не меняет draft. Можно изменить товар существующего варианта модификатора, сохраняя его количество/доплату/название POS.
- «Где используется»: прямые и вложенные родительские рецептуры, число native-чеков с товаром или его списанием, число отложенных заказов с прямой позицией товара. Родитель открывается по нажатию. У ещё не сохранённого товара отображается пояснение; ошибка чтения не изображается нулевыми счётчиками. История Web, оставленная в ранее согласованном TODO, не выдаётся за подключённые native-чеки.
- Несохранённые изменения: «Сохранить и продолжить», «Не сохранять», «Остаться в карточке». Переход в другую рецептуру выполняется только после успешного сохранения/отмены текущей. Неудача записи оставляет редактор и введённые данные.
- P09: удаление с подтверждением и проверками использования. Чеки, складской ledger, рецептуры, модификаторы и активные операции не повреждаются при отказе удаления.

CSV-функции присутствуют в исходном JS как утилиты, но у закреплённого renderProductsScreen нет кнопки/вызова openProductImport. Новый отдельный маршрут CSV в интерфейс не добавлялся. JSON-восстановление остаётся в подключённом разделе резервных копий.

## Согласованные границы и native-инварианты

Модуль09 (сайт/онлайн-меню/публикация) по-прежнему TODO по решению владельца. Эти каналы явно помечены в категориях и редакторе, не изображают сохранение/синхронизацию. Модуль06 и зал/бронирования не добавляются.

Тип и базовая единица сохранённого товара остаются закреплёнными, как в действующих native-контрактах: их смена без отдельного преобразования истории небезопасна. Исторически использованный товар не удаляется разрушительно, в отличие от свободного удаления Web. Обозначение ограничено 3 графемами; артикул80, заметка2000; ошибка валидации не обрезает данные молча. Сохраняется существующий durable draft с понятным сообщением при возврате в каталог. Сохраняются административная сессия, её отзыв и repository-level guards.

Расчёты списка используют RecipeCalculator, а не приблизительные формулы UI. Для импортированных recipe-batch товаров себестоимость и физическая доступность считаются на весь выход рецепта; обычные native товары — на продаваемую единицу. Цена и складские факты не пересчитываются произвольно. Низкий остаток отмечается по сохранённому порогу.

## Хранение и резервные копии

ProductDetails — необязательное дополнение ProductInput/draft; null сохраняет прежнее поведение старых вызывающих use cases и fingerprint. Явные поля входят в новый fingerprint. Новый документ `catalog-product:<id>` version1 записывается вместе с продуктом, revision/result/audit/ledger в прежней admin-транзакции. Сбой после записи продукта откатывает также metadata. Удаление разрешённого товара удаляет локальный документ той же транзакцией. SQL-схема не менялась.

При чтении: локальные поля → неизменяемый Web sidecar → сохранённый исходный Web-файл → пустые значения. Исходный sidecar не переписывается: локальные правки имеют приоритет отдельно. Обозначение подключено к рабочей зоне. Native restore validator принимает/проверяет новые документы, их product ID и revision; старые копии/draft без них читаются по-прежнему. Реальная пользовательская копия в этом инкременте не импортировалась.
