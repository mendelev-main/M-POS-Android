## Перенесённые сценарии

Источник: pinned Web `openTelegramSettings`/`saveTelegramSettings`, `shifts.js`/`sendTelegramShiftOpened`/`sendTelegramShiftClosed`, `previousCalendarMonthRange`/`maybeSendMonthlyWarehouseReport`, Android `TelegramClient`/`MPosShiftReceipt`/`MPosShiftReceiptImage`, `MPosWarehousePdf`. Действующий контракт HTTP проверен по [Telegram Bot API](https://core.telegram.org/bots/api). Используются Kotlin/OkHttp/Android Canvas, без JS или WebView.

| Сценарий | Поведение |
|---|---|
| Настроить Telegram | Модальное окно в сетевых настройках; токен с Показать/Скрыть, группа, тема, включение, флаги смен/месячного PDF |
| Проверить | Проверка полей, затем одно `sendMessage` с HTML в указанную группу/тему; включать общий флаг для теста необязательно |
| Сохранить | Проверка admin generation/revision, зашифрованная локальная запись; закрытие только после сохранения |
| Открытие смены | После успешного сохранения смены отправляется имя сотрудника/время, если Telegram и флаг включены |
| Закрытие смены | После сохранения отправляется PNG чека-отчёта с HTML-подписью; суммы берутся из native сохранённого учёта, не пересчитываются сетью |
| Ежемесячный складской отчёт | PDF за предыдущий календарный месяц, включая переход года/високосный февраль; запускается при административном входе, открытии смены/сохранении настройки и раз в час работающего процесса |
| Ручное восстановление отправки | Из настроек: последняя закрытая смена или PDF за прошлый месяц; используются сохранённые настройки, при несохранённых правках кнопки отключены |
| Перезапуск | Настройки читаются из шифрованного файла; журнал событий/месяца защищает от автоматических повторов уже отправленного/неопределённого сообщения |

По правилу исходного Web ежемесячный складской отчёт требует административного доступа; при закрытой admin-сессии он ожидает следующего входа. Это не Android background service: закрытое/остановленное приложение само не отправляет PDF. Для открытия/закрытия смены admin-вход не нужен: используется ранее сохранённое разрешение на уведомления.

## Вид и данные документов

PNG смены использует исходный шаблон Web Android:720px, monospace, заголовок, сотрудник, открытие/закрытие, количество чеков, наличные/карта, начало/внесения/изъятия, ожидается/фактически/разница, движения, подпись. Поддержаны длинные строки; ограничение фотографии Telegram явно останавливает слишком длинный документ, не обрезает движения. Деньги в строках — BigDecimal/копейки, без Double-округления. Принятые ранее native правила возвратов по дню события сохраняются; старый Web-пересчёт прошлых продаж задним числом не возвращается.

PDF использует исходный альбомный шаблон842×595 с пагинацией: упрощённый учёт, сводка с отдельными единицами, движения/остатки, поставщики, реестр накладных и примечания. Оценка прошлого остатка — по текущей себестоимости с явной подписью; неизвестные данные отмечаются прочерками/предупреждениями. До подключения реквизитов организации заголовок — M-POS, без зашитого названия чужой компании.

## Хранение и ошибки

Токен и ключ будущего backend находятся только в AES-GCM файле `noBackupFilesDir/telegram-settings-v1.enc`; ключ AES — Android Keystore. Публичные toString/ошибки не выводят токен/URL с токеном. Парольные поля не попадают в rememberSaveable/savedInstanceState. Изменение/потеря ключа или повреждение файла дают отказ чтения, без подмены данных пустой конфигурацией. Отправка и сохранение — разные действия; тест не сохраняет введённый токен.

HTTP: `sendMessage`, `sendPhoto`, `sendDocument`, HTML, необязательный message_thread_id. HTTPS, bounded timeouts, без redirect/retryOnConnectionFailure. Ошибки401/403/400(chat/thread)/429/DNS/TLS/timeout переводятся в безопасный текст. Ответ должен содержать `ok:true`. Тесты используют только loopback MockWebServer или fake transport.

Перед автоматической отправкой сохраняется `sending` marker. `sent` не отправляется снова. Сетевой обрыв или сбой записи после передачи дают `unknown`: автоматического повтора нет, сначала проверяется чат, затем возможна явная ручная отправка. HTTP429 с retry_after даёт отложенный безопасный повтор месячного задания после дедлайна при очередном запуске проверки. Другой определённый отказ требует исправления настроек/ручного повтора. Журнал не является гарантией доставки: при завершении процесса между сохранением кассовой операции и постановкой Telegram-задания сообщение может потребовать ручной отправки. Ошибка Telegram не откатывает смену, оплату, склад или кассу.

Настройки device-local, не включены в текущий backup/импорт Web и не содержат общий токен бота. Каждая установка задаёт собственного бота и чат. Мультитенантное переключение нескольких организаций в одной запущенной установке сейчас не реализуется.

## Граница backend

Поля ID устройства/владельца сохранены для будущей интеграции; онлайн-переключатель отключён с пояснением. В дополнительном блоке можно сохранить собственный HTTPS URL и ключ устройства. Сейчас эти значения никуда не отправляются: нет синхронизации backend, приёма онлайн-заказов, getUpdates, смены webhook или команд владельца. Это сохраняет старого бота/Web в работоспособном состоянии. Scope09 остаётся TODO по решению владельца.
