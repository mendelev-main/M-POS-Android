## Динамика и ограничения

ReportTrends строится после ReportGroups из одного history списка. Revenue=total продаж−total возвратов; profit=тот же signed total−историческая себестоимость, без courier. Возврат использует себестоимость исходного чека и дату возврата. По local dates в ReportPeriod.zone, пустые интервалы0; не24часовые окна. Длинный период агрегируется максимум в31последовательный календарный интервал, полный охват включительно; сверяется сумма выручки и gross profit с итогом.

Canvas переводит BigInteger в Float только после нормализации для экранной геометрии; бухгалтерские числа не меняются. Линия/заливка сохраняют отрицательную часть относительно нуля. Выбор точки касанием показывает дату/интервал и сумму. Кольцо/сегменты строятся только для корректных неотрицательных распределений; при нулевом/отрицательном раскладе остаются подписанные суммы/прочерки и нейтральное кольцо, без ложных процентов. Не используются demo/fake значения или current recipe.

База не мигрирует; SalesReport.trend добавлен как optional поле для совместимости остальных потребителей. Сетевые эффекты/Telegram/принтеры не вызываются. Большая история по-прежнему читается существующим repository целиком; ограничение31точек оптимизирует только график.
