# Решения и вопросы

Принято в 00: нативный Kotlin/Compose, API 28+, package `com.mendelev.mpos`, debug `.debug`, локальные транзакции Room при реализации 01, стабильный отдельный signing key, функциональность переносится с pinned Web commit. Ни Web код, ни его ключи не меняются.

Открытые решения не блокируют bootstrap:
- Перед 01: удаление/архив товара с зависимостями, точные обязательные поля, целевые размеры планшета. До ответа использовать безопасный запрет удаления связанных записей и адаптивную ширину; зафиксировать решение при реализации.
- Перед 03: валюта/decimal scale, rounding и границы скидок, смысл ручной цены/частичной оплаты; подтвердить исходными scenarios/fixtures, не догадкой.
- Перед 05: матрица ролей и способ локальной аутентификации; секреты не сохранять открытым текстом.
- Перед 07: реальные обезличенные версии backup, политика замены/слияния, объём истории/фото.
- Перед 08: модель LAN-принтера/бумага и доступность физического оборудования; Telegram sandbox.
- Перед 09: исследовать backend contracts и тестовое окружение, retry/idempotency/menu ownership. Production endpoint/key сюда не вписывать.

Изменения решений оформлять датированной записью: причина → затронутые acceptance IDs → миграция → проверки.

## ADR-002 — целевой стек, 2026-10-24

По запросу пользователя стек описан исходя из полного функционального соответствия Web. Решение: [STACK.md](STACK.md). Уточнены Lifecycle/Coroutines/Navigation Compose, Hilt, Room/KSP, DataStore, serialization, Coil, OkHttp/streaming SSE и WorkManager; платформенные адаптеры файлов, печати, отчётов и секретов. Выбраны роль каждой технологии и этап подключения, без установки новых dependencies в этой документационной задаче.

Деньги/единицы остаются в Kotlin domain, операции — в Room transactions; WorkManager не подменяет постоянный realtime transport. Версии будущих библиотек проверяются при подключении, текущая CI-проверенная база сохранена. Поведенческие P/W/S/I/H/C/B/D/N критерии и порядок этапов не изменены.


## ADR-003 — правила каталога/черновиков для реализации, 2026-10-24

По задаче детализации документации приняты безопасные native правила P/W в [CATALOG-WORKSPACE-SPEC.md](CATALOG-WORKSPACE-SPEC.md): стабильные categoryId, запрет удаления связанных объектов, явный opening stock movement, отсутствие прямой перезаписи остатка карточкой, optimistic revision и повторяемые команды, атомарный перенос current/parked, revalidation изменённого каталога. Некорректное число не становится нулём как при Web parseFloat fallback. Отрицательная цена товара запрещена, нулевая требует ручной цены.

Это решения для будущего кода, не уже созданная схема/миграция. Возможные последствия: первая Room schema должна поддержать revisions/связи и opening movements, 02 — устойчивые sessions, 03 — исторические snapshots. Контроль: fixtures CAT/UNIT/RECIPE/MOD/STOCK/CART/PARK/DRAFT в [IMPLEMENTATION-CONTRACTS.md](IMPLEMENTATION-CONTRACTS.md).

Открыты до соответствующих этапов: точные лимиты полей/изображений (01), денежные fixtures/валюта/rounding/частичный возврат (03), оценка закупочной стоимости (04), роли/бизнес-день (05), server loyalty/consent (06), replace/merge backup (07), профиль оборудования (08), API payloads/idempotency/ownership (09). Протокольные наблюдения Web не считаются согласованным backend контрактом.


## Системное уточнение ADR-003 — 2026-10-24

Документированы владельцы данных/версии, независимые состояния заказа/оплаты/эффектов, fingerprint команд, фото staging, требования миграции/restore/outbox и аудит. [Системная приёмка](SYSTEM-ACCEPTANCE.md) связывает их с существующими IDs. Реализация Room и новые продуктовые функции не начинались.

Дополнительные открытые gates: перед 01a задать денежную единицу цены каталога и decimal storage limits; перед 01b — precision неконечного recipeYield division; перед03 — минимальные правила активной смены, поскольку полный этап05 позже. При необходимости минимальный shift/domain contract переносится в03 явным уточнением плана. Предложенная capabilities matrix не утверждает окончательные роли. Протокол dataset activation и системный Android backup/extraction требуют проверки при реализации, не считаются готовыми по этому описанию.
