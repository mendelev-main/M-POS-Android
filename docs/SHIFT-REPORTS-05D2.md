- RS01: список смен, пересекающих выбранный календарный диапазон; итоги каждой строки за **всю смену**, включая события за пределами фильтра. Открытая смена предварительная. Это не сумма календарных карточек выше. Открытие/закрытие и кассир из исторического shift snapshot. Пустые смены также видимы.
- RS02: касса = opening + cash sales − cash refunds − courier out + courier refund credit + deposits − withdrawals. Карта показывается отдельно, сдача не удваивается. Возврат относится к смене фактической выдачи; исходная продажа остаётся в исходной смене. Остаток предыдущей смены переносится только через сохранённый opening, не складывается повторно. Незавершённые split parts не являются финальной продажей.
- RS03: для закрытой смены сравнить расчёт с сохранённым expected и counted−expected с сохранённым difference. Расхождение явно показать; не перезаписывать закрытую смену. Фактическое отличие counted от expected допустимо и показывается отдельно. Неизвестные/повторные/внесменные события — ошибка чтения, не нули.
- RS04: для продаж/возвратов выбранных дат сравнить ожидаемые движения из immutable consumption/stock со ledger: source/document/product/command/time/exact delta. NoStockTracking из исходного чека не создаёт ложного ожидания. Проверять также строки с правильной ссылкой, но неправильной датой, и orphan финансовые движения периода. Пропуск/повтор/лишнее/несовпадение явно показать. Снимок возврата должен совпадать с исходным чеком.
- RS05: единая admin read transaction для сводки, групп, смен и сверки. Нет чтения текущих карточек для расчёта, инициализации или auto repair. Logout/epoch поведение экрана сохраняется.

Граница сверки RS04 — списания продаж и восстановление возвратов. Это не утверждение полной сверки всех остатков/стоимостной оценки/приёмки/инвентаризации. Их документы доступны в проверенном04c.2; начало/конец исторических остатков и стоимость склада остаются отдельным объёмом. Количества разных товаров/единиц не складываются.
