## Контракт

- RG01: группы сотрудников по историческому ID кассира смены. Возврат относится к автору продажи, исполнитель возврата остаётся в журнале операций. Полная сумма чека включает доставку.
- RG02: товары и категории по ID и сохранённым названиям/категориям. Суммы строк берутся после скидок из оплаченного чека, доставка не распределяется на товары. Переименование одного ID сохраняется списком исторических названий; одинаковые имена разных ID не объединяются.
- RG03: проданное и возвращённое количество раздельно по единицам. 2шт. и1,5кг не превращаются в3,5. Сортировка — сумма продаж по убыванию, затем ID, а не сравнение разных количеств.
- RG04: себестоимость каждой строки по сохранённому графу рецептуры, выходу и выбранным модификаторам, включая noStockTracking. Точные рациональные промежуточные значения, один HALF_UP до копейки на строку, затем сумма строк. Две строки по0,005 →0,02BYN; сумма накладной и текущая стоимость не переписываются.
- RG05: прибыль = продажи − возвраты − (себестоимость продаж − себестоимость возвратов) − (выдача курьеру − отмена выдачи). Чек25, стоимость8, доставка/выдача5 →12BYN; полный возврат отменяет12 в день возврата. Это прибыль по товарам/доставке без налогов и прочих расходов предприятия.
- RG06: единый read-only admin snapshot сводки и групп в Room transaction. Нет загрузки текущих товаров/сотрудников, записи, миграции или новых внешних эффектов. Повреждённая история вызывает ошибку, не подстановку нулей. UI не показывает денежные группы после logout и не сохраняет их в SavedState.
