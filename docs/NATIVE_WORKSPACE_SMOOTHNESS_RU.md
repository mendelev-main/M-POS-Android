# Рабочая зона: стабильные обновления и цвета кнопок

08.10.2026. Исправление качества этапа 101 по замечанию владельца: отличие цвета кнопок и мерцание при нажатиях. Используется актуальная локальная копия основной ветки main; финансовые операции и права не меняются.

## Что изменено

- Обычное обновление количества, цены, остатка, метаданных и итогов сохраняет существующие Android Views, сетку и scroll containers. Вместо removeAllViews выполняется обновление изменившихся текстов и доступности.
- У карточек есть стабильный ID типа/товара, у строк корзины — cart line ID. Добавление, удаление и перестановка строк меняют только соответствующие строки; остальные Views сохраняются. Строки доставки/скидки/итога также согласуются отдельно.
- Ключи действий и token обновляются вместе с моделью: сохранённая кнопка обращается к текущему действию, удалённая кнопка не может вызвать старую операцию. Swipe использует текущий removeKey. Stale completion не снимает busy новой операции.
- Busy по-прежнему блокирует повторные действия; рабочие кнопки сохраняют обычную палитру вместо кратковременного серого disabled состояния. Настоящие disabled/blocked действия остаются визуально недоступны.
- Shared MPosNativeTheme и адаптеры рабочего места/форм различают cash, card, primary, secondary, outline. Наличные используют accent, карта — navy #22273A / #10131A с белым текстом, secondary — фон, outline — прозрачный фон с границей. Шрифт, отступы и доступность сохраняются.

## Границы

Полное построение рабочего места остаётся при изменении категории/папки, состава или геометрии каталога, темы, масштаба шрифта, размеров окна и структуры панельных действий. Это осознанные смены структуры; обновление строк корзины и денежных итогов структуры рабочего места не меняет.

Карточки/значения пока поступают через действующий presentation adapter; нативные read models относятся к 109.09. WebView не удалён. Перестроение других нативных экранов/форм требует отдельного аудита. Общая плавность всей кассы, FPS и физическое отсутствие мерцания пока не подтверждены измерениями.

Для отката только нового способа обновления установить MPosNativeWorkspaceRetainedViewsEnabled=false; прежнее полное построение сохраняется. Полный rollback рабочего места — существующий MPosNativeWorkspaceEnabled=false.

Не пересчитывать бизнес-остатки или деньги в renderer. При добавлении позиции существующие владельцы операций/расчётов формируют значения, UI отображает результат. POS сохраняет данные до внешних действий, backup v13 и availability policy прежние.

## Проверка

Написаны JS проверки стабильных IDs/цветовых ролей и JVM проверки identity Views при обновлении остатка/количества/суммы, пустой/наполненной корзины, перестановки/удаления строк, доставки/скидки, актуальных action keys/tokens, stale completion и busy palette. Старые проверки detached controls выполняют настоящую смену контекста; на обычном обновлении Views должны оставаться действующими.

Локально выполнены только node --check для изменённых адаптеров и git diff --check. Unit tests, lint и APK выполняет GitHub Actions по AGENTS.md §17; результат не заявлен заранее. Новые превью локально не генерировались, физическая приёмка pending.

На планшете проверить: 20 последовательных добавлений одной позиции и 20 разных позиций; остаток/количество/итог после каждой завершённой операции; удалить/переставить/очистить корзину; доставка и скидка; обе темы; scroll position; крупный шрифт; смена категории/папки; быстрые повторные нажатия не создают дубли; возврат из оплаты/настройки сохраняет рабочее состояние. Оценить кадры Android frame profiler на устройстве, ориентируясь на период обновления его экрана, а не только субъективную скорость.

Исправление не закрывает новые migration IDs. Текущий срез после обновления main: 107/110; 109 — 7/20; детально 114/129 (88,37%), осталось 15. Рост относительно 113/129 обусловлен уже завершённой в основной ветке 109.07.
