# «Состав и остатки»: Web → Kotlin

Источник — pinned `product-configuration.js` (`renderTypeFields`, componentBaseQty/addComponent/inferredCompositeYield) и `.product-editor` CSS в pos.html. Реализация локальная, окончательную визуальную приёмку выполняет владелец в Android Studio.

## Простой товар

Порядок Web: разрешение отрицательного остатка с пояснением, единица ввода, себестоимость и текущий/начальный остаток рядом, закупочная упаковка, минимум, «Не вести учет остатков». По уточнению владельца13.11.2026 себестоимость простого товара можно изменять и сохранять в карточке. Пересчёт единицы ввода в базовую, admin/revision/transaction guards сохранены. Ручная правка не создаёт движения количества и не меняет историческую стоимость продаж. Приёмка сохраняет отдельный механизм средневзвешенной стоимости; себестоимость составного товара рассчитывается по рецептуре.

Кг↔г и л↔мл пересчитывают количества и стоимость ввода, без изменения цены продажи/истории. Базовая единица сохранённого простого товара не меняется. Остаток редактируется без причины, с прежними revision/ledger guards. При отключённом учёте поле остатка недоступно, данные остатка не обнуляются.

«Как обычно закупаем»: единица закупки, количество внутри, единица внутри. Например,500г внутри упаковки при базе кг сохраняет0,5кг, а предпочтение г возвращается при открытии карточки. Черновик хранит исходный текст дробного ввода, пересчёт производится при формировании ProductInput. Переключение display unit не меняет отдельно выбранную единицу упаковки.

## Составной товар

Выход готового состава — вес/объём и единица. Автоматический выход однородного состава:200г+50г→250г, объёмы→мл, счётные→шт. Разные измерения не складываются. Ручное изменение выхода/единицы отключает авторасчёт, как Web; флаг переживает сохранение/черновик. Для старых карточек без флага сохранённый выход считается заданным вручную. Импортированный recipeYieldManual читается из immutable sidecar без его изменения.

Карточки ингредиентов содержат название/категорию, стоимость строки, количество/единицу и единый крестик удаления. Ниже — встроенный поиск с очисткой, категории, виртуализированный список и «Добавить»/«+ ещё». Повторное добавление увеличивает существующую строку. 0,0004кг↔0,4г сохраняет физическое количество без округления до тысячных. Вложенный ингредиент задаётся физическим выходом:1г рецепта с выходом200г означает1г, не200г. Прямые и косвенные циклы отклоняются до изменения черновика.

Итог состава вычисляется из физических запросов ингредиентов, независимо от продажи; старым native-товарам с продажей по единице выхода показано соответствующее пояснение. Новые составные, созданные через редактор, продаются целым рецептом, как Web: выход300г, расход0,3кг муки — одна позиция списывает0,3кг. Существующие stock-unit товары автоматически не мигрируются; импортированный recipe-batch сохранён. Боковая сводка учитывает действующую модель продажи.

Единица выхода сохранённого составного товара редактируется с проверкой всей цепочки рецептов. Несовместимые родители или открытые заказы с прежней единицей отклоняют всю транзакцию; уже оплаченные части по-прежнему защищены. Тип сохранённого товара менять нельзя.

## Хранение и восстановление

`catalog-product:` содержит новые необязательные sellingBasis/recipeYieldManual/purchaseContentUnit. Старые документы v1 и черновики читаются. Для новых полей encode использует v2: старая версия приложения отклонит неподдерживаемую модель, а не восстановит рецепт как продажу по единице. Fingerprint v1 сохранён для прежних трёх полей, новые значения участвуют в v2 fingerprint. Room schema не менялась.

Workspace, список товаров и editor используют local basis с прежним fallback Web. Native restore проверяет формат, тип товара и совместимость упаковочной единицы. Оригинальный Web ZIP, immutable metadata и исторические чеки не переписываются.

## Проверки

ProductStockRulesTest — авто/ручной выход, вложенность, цикл, повторное добавление, единицы, упаковка, старые fingerprints/drafts. ProductStockStoreTest — read-only cost, продажа целого рецепта, rollback при смене единицы открытого заказа, сохранение и native snapshot validation. ProductStockPanelTest — поиск/добавление/+ещё/стоимость/единица/удаление в отдельной in-memory базе, без проведения продажи или изменения сохранённых товаров. Старые CatalogConfigurationUiTest и тесты шапки адаптированы; наличие кода не означает pixel-verified.
