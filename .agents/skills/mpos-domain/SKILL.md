# Домен M-POS

Прочитайте `docs/DATA.md`, соответствующие acceptance IDs и предметные пути `docs/SOURCE.md`. Исследуйте исходный handler вместе с Android adapter: один исходный JS-файл может не отражать фактическое Web-поведение.

Опишите вход, сохранённое состояние, результат и отказы в конкретных примерах. Для 01/02 используйте P/W; для оплат/возвратов уточните decimal/rounding policy перед кодом. Не переносите ошибки Web ради формального совпадения: расхождение с основанием и тестом записать в context.

Расчёты Kotlin не зависят от Compose/Context. Денежные decimal значения и складские единицы не смешивать с форматированием. Проверить noStockTracking/allowNegativeStock отдельно по каждому simple ingredient, recipe yield, вложенность, модификаторы и резервы. Циклы рецептуры и невалидные единицы отвергать.

Финансовый use case атомарно сохраняет снимок, движения, сессию и outbox; сеть/печать после commit. Права проверяются внутри команды. Возврат использует исторический расход. UI disabled не заменяет idempotency key и transaction concurrency.

Тестировать наблюдаемые границы: дробный расход 0.0004 кг, повтор команды, отказ записи, restart, смена рецептуры до возврата, stale inventory baseline. Не писать Kotlin-тесты, которые лишь ищут текст исходника. Для persistence добавить Room tests и migration fixtures, для pure math — JVM tests. Запишите существенное расхождение/неизвестность, не придумывайте backend API.
