# Этапная работа M-POS

Прочитайте `AGENTS.md`, `PLANS.md` и файл этапа `harness/build/NN-*.md`. Установите зависимости и точные acceptance IDs. Прочитайте существующий context и результаты в `harness/build-log.md`; не считать старый planned статус evidence.

До реализации сверьте предметный сценарий с pinned Web revision из `config/reference.json`: найдите feature, Android adapter и регрессионный тест. Читайте только нужные файлы. Если исходник/документ расходятся, запишите обнаруженное поведение и выбранное решение в context. Обновление reference commit — явное изменение требований, а не автоматический fetch HEAD.

Разбейте текущий этап на обозримые изменения, каждое с наблюдаемым результатом. Создайте context при начале этапа. Сначала реализуйте вертикальный сценарий с хранением и тестами, затем остальной UI. Не начинайте следующий этап без задачи на него. Обычные исправления внутри поставленной задачи не требуют нового согласования.

После изменений выполните `python3 scripts/harness.py preflight`; для кода — `python3 scripts/harness.py android`, для UI/Room — подходящие instrumentation tests. При отсутствии среды записать blocker и оставить проверки pending.

Обновите parity для точных IDs. В журнале укажите commit, команды/Actions URL, наблюдаемый результат и незакрытые device cases. В context хранить решения/ограничения, а не полный транскрипт и не секреты. Завершение этапа требует его acceptance, частичное выполнение так и назвать.
