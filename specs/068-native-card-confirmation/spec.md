# 068 — Нативное подтверждение оплаты картой

Цель: заменить целый HTML modal терминального подтверждения нативным Kotlin UI.
Общий экран оплаты/смешанные части пока WebView; это не полный выход из WebView.
Используем Android AlertDialog/Views, как текущие native shift forms; Compose
ещё не подключён. UI содержит прежние инструкцию, сумму, «Отмена», «Оплата прошла».
Светлая/тёмная тема передаётся с текущего экрана.

MPosCardConfirmationDialog обслуживает новый paymentScreen bridge channel.
Показывает один transient token/amount/amountLabel/theme. Денежную строку пока
формирует действующий fullMoney, чтобы сохранить формат валюты без второй логики.
Нативный диалог не читает/пишет Room, не вызывает сеть/терминал и не инициирует чек.
После положительного ручного подтверждения вызывается прежний callback:
полная оплата → finalizePayment; часть → completeSplitPayment. Сохранение,
повторная проверка stock/pricing, печать, Telegram, availability не меняются.

Нативная кнопка потребляет token один раз. Замена окна/программное закрытие/
уничтожение Activity dismiss без подтверждения. Старый hide/старые кнопки не
закрывают и не подтверждают новое окно. Отмена кнопкой/Back/outside передаёт cancel;
JS вызывает closeModal и renderSplitPayment, как исходник. Изменение корзины,
скидок/подарков/клиента/доставки/частей/смены или незавершённая операция отменяет
устаревшую попытку подтверждения с сообщением, без записи чека/части.

Как и ранее, кассир подтверждает внешнюю оплату вручную. Приложение не проверяет
успех терминала и не может автоматически отменить проведённую оплату; если заказ
изменён или локальное сохранение отклонено, нужна проверка фактического платежа.
Это существующая бизнес-граница, кандидат будущей интеграции терминала.

Rollback: MPosNativeCardConfirmationEnabled=false возвращает reviewed HTML.
При отказе postMessage до отправки также остаётся HTML callback; неизвестный
результат уже отправленного подтверждения не запускает повторный callback.
Исходный payment.js неизменён. Формат чеков/частей, legacy ключи, backup v13
не меняются; нативный callback не хранится в данных.

Проверки: Robolectric реальный диалог/обе темы/сумма/повторные кнопки/Back/
замена/устаревший hide/невалидная сумма/нулевая сумма. JS реальные handlers:
отсутствие HTML и сохранения до confirm, single callback, cancel, stale,
rollback/rejected bridge. Общие JS/JVM/lint обязательны, APK собирает GitHub.
Физические проверки внесены в общий список и отложены до общей приёмки.
