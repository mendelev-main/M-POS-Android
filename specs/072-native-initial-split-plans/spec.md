# 072 — первоначальное распределение смешанной оплаты

Kotlin MPosSplitPaymentPlans рассчитывает исходные части: сумма округляется
в копейки по правилам JavaScript Math.round, целая доля выдаётся каждой
части, остаточные копейки получают первые части. Сохраняются cash, paid=false,
cashGiven=null, change=null. Движок поддерживает 2–10 частей.

Рабочий cutover: существующий cartTotalsRead возвращает начальный план для
двух частей (обычное первое открытие смешанной оплаты). Никаких дополнительных
запросов, таблиц или записей. Не строим девять ненужных вариантов при каждом
quote. JS buildSplitPayments использует только валидный план для совпадающего
снимка корзины, суммы и количества; возвращает независимую копию.

Отсутствующий/просроченный quote, другой count, небезопасные числовые значения
или rollback сохраняют reviewed source. MPosNativeSplitPlansEnabled=false
отключает cutover; MPosNativeCartTotalsEnabled=false также отключает его.

Редактирование, normalizeSplitPayments, изменение количества, сохранённые
оплаченные части, progress commit и финальная оплата не меняются. Полная
миграция смешанной оплаты пока не завершена. Следующий участок — изменение
неоплаченных частей с сохранением оплаченных сумм. Source payment.js неизменён;
backup v13, Room, остатки, Telegram и прочие внешние эффекты не затрагиваются.

Проверки: 126 исходных fixtures (14 сумм × 9 количеств), прямой JS reference,
Kotlin совместимость, независимость копий, stale/rollback/невалидный план.
Физические проверки отложены: открыть смешанную оплату 10,01 → 5,01 + 5,00;
изменить количество частей/методы, оплатить одну часть, перезапустить и завершить;
сверить чек и единственное списание остатков. Локальная APK не собирается.
