# 074 — редактирование суммы части смешанной оплаты

## Область

MPosSplitAmountEngine владеет read-only решением splitAmountRead: авторитетная
проверка строки ввода, ограничение суммы, округление, paid/previous-unpaid
суммы и распределение остатка. До десяти частей, без сканирования Room, stock,
чеков, сети или записей. UI keypad/его первичная parsePaymentNumber gate пока
reviewed JS; engine повторяет проверку перед расчётом. Это не перенос всего
payment shell/всех callers парсера и не закрытие normalize (075).

## Совместимость

JS whitespace (включая NBSP/FEFF) удаляется; только первая запятая заменяется
точкой. Допускаются цифры и 0–2 знака после точки, без знака/экспоненты.
Пустое/промежуточное/невалидное значение и paid target не изменяют строки.
Paid и предыдущие unpaid округляются в копейки поштучно (в отличие от 073,
где сначала суммируются paid). Requested ограничен оставшейся после них суммой.
Следующие unpaid получают остаток, лишние копейки первым. При редактировании
последней unpaid остальные unpaid (включая предыдущие) получают разницу.
Сумма и порядок paid, методы/дополнительные поля/identity всех частей сохранены.
Очищаются cashGiven/change только у edited строки. Другие tender поля остаются.
Backup v13, progress commit, финальная транзакция и внешние эффекты неизменны.
Ошибочные/небезопасные числовые данные не дают изменённого результата.

## Очередь и UI boundary

Общая FIFO SplitPayments сериализует count и amount; payment/pre-existing
native confirmation guards уже ждут её. Новая операция count разделяет
группы редактирования. Последовательные ещё не начатые вводы одной и той же
строки объединяются в последнее валидное значение; in-flight не переписывается.
Это ограничивает лишние запросы при быстром вводе, не обещает отсутствие
bridge на каждом медленном нажатии. Native keypad — будущая UI задача 103.
Существующий HTML keypad обновляет суммы после ответа; физическая отзывчивость
подлежит общей приёмке. Очередь не отправляет весь каталог/архив.

Закрытие/смена заказа/перестановка target/изменение context/critical operation
отменяют late reply. Неуспешный bridge/невалидный ответ не меняет строки;
повтор вручную, без critical-storage uncertainty. Rollback:
MPosNativeSplitAmountEnabled=false. Source payment.js неизменён; исходный
синхронный обработчик сохранён. Count rollback не отключает общую FIFO amount.

## Проверки

145 source fixtures: оплаченная/несуществующая/средняя/последняя строка,
промежуточный ввод, запятая/точка/whitespace, cent tie, большая requested сумма,
нулевые/малые суммы, tender/extra fields. Kotlin точно сравнивается с source;
проверяются неизменность input, Unicode whitespace и overflow. JS покрывает
coalescing, count barrier, identity/paid, stale/error/protocol/rollback.
Отдельные bridge tests проверяют correlation, frozen payload и отсутствие записи.

## Физическая приёмка — ожидается

Заказ 10,00: paid 2,00 + unpaid 4,00 + 4,00. Ввести среднюю 3,00 →
2,00 paid + 3,00 + 5,00. Ввести последнюю 1,00 → 2,00 paid + 7,00 + 1,00.
Быстрый 1→12→12,34, Backspace до пустого, запятая, +/- между вводами;
оплата во время ответа, закрытие/перезапуск, единственный итоговый чек/списание.
Локальную APK не собираем.

## Спорные правила для возможного будущего рефакторинга

«Последняя строка» не всегда точный остаток: исходник допускает указанную
меньшую сумму и меняет предыдущие unpaid. Сохраняет tender у этих соседних
строк, хотя их amount изменился. Эти политики не меняем в миграции.
