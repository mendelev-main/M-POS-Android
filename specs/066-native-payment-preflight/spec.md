# 066 — Проверка остатков перед оплатой через Kotlin/Room

Проверки открытия оплаты, подтверждения наличных/карты и начала оплаты части
используют существующий MPosStockPreflightRepository и MPosRecipeConsumptionEngine.
JS передаёт только идентификаторы, количество и модификаторы. Каталог читается
из Room, без резервирования, списания, записи или сети. Финальная транзакция
продажи повторно проверяет и списывает остатки атомарно.

Исходные payment.js и оформление сохраняются. Проверка тарифа, пустой корзины
и открытой смены сохраняет порядок. Серверная проверка подарка выполняется после
остатков; её callback повторяет проверку Kotlin. Подтверждение карты остаётся
отдельным действием, часть смешанной оплаты не становится оплаченной от preflight.
Нативное решение подменяет canFulfillCart только внутри синхронного вызова
исходного обработчика, с обязательным восстановлением в finally.

Повторный тап во время чтения отклоняется; очередь изменений корзины не допускает
оплату. Закрытие модального окна/страницы, изменение корзины, денежных/клиентских
данных, каталога, смены или начало другой критической операции отменяет устаревший
ответ. Ошибка чтения не помечает хранилище повреждённым и не запускает JS fallback.

Совместимость: ключи и backup v13 без изменений. Rollback:
window.MPosNativePaymentPreflightEnabled=false.

Сохраняем существующее правило: preflight ничего не резервирует. Остаток может
измениться после подтверждения карты; финальная транзакция тогда отклонит продажу.
Уже проведённые внешние платежи нельзя автоматически отменить локальной проверкой;
изменение этой политики требует отдельного бизнес-решения.

Проверки: реальные исходные payment handlers в VM, наличные/карта/части,
серверный gift callback, нехватка/timeout/невалидный ответ, отмена/изменения,
повторные тапы/очередь. Полные JS/JVM и lint; APK собирает GitHub.
Физические кейсы остаются в общем приёмочном списке.

Результат проверки: 212 JS tests passed; 213 JVM tests без ошибок/пропусков
(Gradle повторно использовал актуальные результаты неизменённого Kotlin).
Lint: 0 errors, 16 существующих warnings.
