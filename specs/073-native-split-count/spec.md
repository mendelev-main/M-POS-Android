# 073 — изменение количества частей смешанной оплаты

## Область и польза

MPosSplitCountEngine рассчитывает увеличение/уменьшение количества (2–10),
оставшиеся копейки и порядок paid → unpaid. Kotlin владеет решением;
Android adapter только применяет подтверждённый снимок и вызывает прежний render.
Чистый read-only splitCountRead проходит через существующую FIFO Kotlin.
Не сканирует Room/каталог/историю чеков, не пишет данные и не резервирует остатки.

## Сохранённые правила исходника

- Оплаченные части неизменны; запрещено уменьшение ниже их количества.
- При изменении paid-части идут первыми, unpaid сохраняют взаимный порядок.
- Удаляются последние unpaid; новые части cash/paid=false/tender=null.
- Paid-сумма сначала складывается, затем округляется в копейки.
- Оставшийся total − paid ограничен снизу нулём; лишние копейки идут первым unpaid.
- Объектные ссылки сохранённых частей сохраняются; изменяется только amount unpaid.
- При границе 2/10 ничего не меняется и renderer не вызывается.
- Обычный источник JSON/v13, progress commit, финальная транзакция/остатки,
  gift eligibility, Telegram и другие внешние эффекты не меняются.

## Асинхронная безопасность и rollback

Быстрые нажатия идут FIFO (лимит 32); оплата и ранее открытые нативные
подтверждения ждут завершения изменения. Отмена/выход, замена корзины,
изменение частей/контекста или critical operation отменяют поздний результат.
Bridge error/невалидный ответ оставляет строки без изменений; повтор вручную.
Read failure не переводит хранилище в режим неопределённой записи.
MPosNativeSplitCountEnabled=false возвращает исходный синхронный обработчик.
Source payment.js неизменён; source synchronization сохраняет adapter.

## Автоматическая проверка

160 source fixtures: 5 сумм × 4 количества × 4 paid-группы × 2 delta;
нулевые суммы, дробные копейки, оплачено больше остатка, all-paid, interleaved
paid, методы и дополнительные поля/tender. JVM точно сравнивает исходные
части и неизменность input. JS проверяет FIFO, identity, late reply, error,
invalid paid row и rollback; общий bridge/preflight контур покрыт отдельно.

## Физическая приёмка — отложена

Сумма 10,01, первая часть картой 5,01 оплачена: увеличить до трёх →
5,01 paid + 2,50 + 2,50; уменьшить → 5,01 paid + 5,00. Быстрые +/-;
попытка оплаты во время расчёта; Back/выход при ответе; перезапуск после paid;
завершить и сверить единственный чек/списание. Локальная APK не собирается.

## Вопросы для будущего бизнес-рефакторинга — без изменений сейчас

Исходник сохраняет прежние cashGiven/change у перераспределённых unpaid и
может оставить ноль у всех unpaid, если paid >= total. Paid-части переезжают
в начало списка. Эти правила сохранены, но для будущей доработки стоит
отдельно решить, нужно ли очищать tender и сохранять визуальные номера частей.

Обновление 074: amount использует общую очередь SplitPayments; count создаёт
barrier между группами ввода. Authoritative ввод/перераспределение теперь Kotlin,
HTML keypad/первичный gate остаются JS. Следующая 075 — normalize/resume draft.
