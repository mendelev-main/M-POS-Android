# Harness

Это рабочий контур: постоянные правила в `AGENTS.md`, предметные skills в `.agents/skills/`, планы в `harness/build/`, решения в `harness/context/`, доказательства в `harness/build-log.md`. `scripts/harness.py` исполняет проверки локально и в CI.

Перед изменениями: определить текущий этап, источники и acceptance IDs. После: выполнить подходящие проверки, обновить статус и записать ограничения. Для денег/остатков отдельно проверить отказ записи, повтор операции, перезапуск и исторические снимки. Для UI — состояние после поворота/перезапуска и планшетную приёмку. Для внешних систем — fake adapters в CI, реальные проверки по отдельной поставленной задаче.

`preflight` работает без Android SDK. `android` требует JDK/SDK и запускает Gradle. GitHub Actions не заменяет физическую проверку принтера/планшета. Ни план, ни отчёт другого проекта не засчитываются как тест этого приложения.

## Кратко: зачем, как и где

**Зачем:** чтобы агент продолжал разработку по утверждённому плану, сохранял правила продукта и подтверждал результат проверками, а не только описанием готовности.

**Как:** перед задачей читаем этап и контекст → сверяем поведение с pinned Web → реализуем небольшой сценарий → запускаем проверки → записываем результат и оставшиеся ограничения. Harness не пишет приложение сам: это правила, документы и команды вокруг разработки.

**Где:**

| Место | Назначение |
|---|---|
| `AGENTS.md`, `.agents/skills/` | Постоянные правила и инструкции для этапов, предметной логики и выпуска |
| `harness/build/` | Границы этапов и критерии приёмки |
| `harness/context/` | Решения и контекст для продолжения работы |
| `harness/build-log.md`, `docs/PARITY.md` | Реальные результаты проверок и степень переноса функций |
| `scripts/harness.py` | Исполняемые проверки структуры и Android |
| `.github/workflows/` | Запуск проверок и выпуска в GitHub Actions |

Команды из корня репозитория:

```sh
python3 scripts/harness.py preflight
python3 -m unittest discover -s scripts/tests -v
python3 scripts/harness.py android
./gradlew connectedDebugAndroidTest
```

Первые две работают без Android SDK; третья требует JDK/SDK, последняя также emulator/device. Проверяем по масштабу изменения. В develop нет автоматической сборки на каждый push; CI для готового PR и выпуска — по [основному workflow](../docs/DEVELOPMENT-WORKFLOW.md). Непройденную или недоступную проверку явно оставляем pending.
